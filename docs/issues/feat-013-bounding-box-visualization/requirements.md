# feat-013: バウンディングボックス描画 要求仕様書

## 1. プロジェクト概要

- **何を作るか**: HALPE 26キーポイント・スケルトン描画に加え、人物検出のバウンディングボックスを動画フレームに描画する機能
- **なぜ作るか**: 現状は人物が検出されたかどうかがキーポイントの有無でしか判断できない。バウンディングボックスを表示することで、検出範囲と信頼度スコアが視覚的に確認でき、デバッグや結果検証が容易になる
- **誰が使うか**: 本プロジェクトの開発者
- **どこで使うか**: CUDA対応GPU搭載のLinux環境

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| バウンディングボックス（BB） | 人物検出モデルが出力する矩形領域。`[x1, y1, x2, y2, score]` の5要素で表現される |
| bbox_thr | バウンディングボックスの信頼度閾値。現行は0.3。この閾値以上の検出結果のみポーズ推定に使用される |

## 3. 機能要求一覧

### FR-001: バウンディングボックス描画

- **機能名**: 人物検出バウンディングボックスの描画
- **概要**: ポーズ推定に使用されたバウンディングボックスを、キーポイント・スケルトンと合わせてフレームに描画する
- **入力**: ポーズ推定結果に含まれるbbox情報（`[x1, y1, x2, y2, score]`）
- **出力**: バウンディングボックスが矩形で描画されたフレーム画像。BBの左上にスコア（小数2桁）を表示する
- **受け入れ基準**: テスト動画（cam05520129.mp4）で、検出された人物ごとにバウンディングボックスが矩形で表示され、スコアが左上に表示されること（目視確認）

### FR-002: 統合パイプラインへの組み込み

- **機能名**: `run_halpe26_pipeline.py` でのBB描画
- **概要**: FR-001の描画機能を統合パイプライン（feat-012）の可視化処理に組み込む
- **入力**: 既存の `--mode both` または `--mode video` 実行時
- **出力**: 可視化動画にバウンディングボックスが含まれる
- **受け入れ基準**: `run_halpe26_pipeline.py --mode video` で出力された動画に、キーポイント・スケルトン・バウンディングボックスが全て描画されていること（目視確認）

## 4. 非機能要求

- **パフォーマンス**: BB描画はOpenCVのrectangle/putTextのみであり、推論処理に対して無視できる程度の処理時間であること
- **対応環境**: 既存と同一
- **互換性**: JSON出力（OpenPose JSON）には影響しない。BB描画は可視化のみに適用される

## 5. 制約条件

- 既存の `merge_halpe26.py` の `draw_halpe26` 関数は変更しない（単一責務を維持）
- BB描画は新規関数として `merge_halpe26.py` に追加する
- 描画色は黄色 `(0, 255, 255)` (BGR) とする（キーポイントの緑・オレンジ・青と区別できる）

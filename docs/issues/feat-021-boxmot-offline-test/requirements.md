# feat-021: 既存JSON+動画でBoxMOT動作検証 — 要求仕様書

## 1. 目的

- **何を作るか**: 既存のOpenPose JSONと元動画を入力し、BoxMOT Deep OC-SORTでトラッキングIDを付与するテストスクリプト
- **なぜ作るか**: ViTPose推論を再実行せずに、BoxMOTの動作確認と基本的なトラッキング結果を確認する。GPU負荷ゼロで最速の動作検証を行う
- **誰が使うか**: 開発者（トラッキング技術の検証）
- **どこで使うか**: ViTPoseリポジトリの既存Python環境

## 2. 用語定義

本ドキュメント、機能設計書、コード内で統一して使用する。

| 用語 | 定義 |
|------|------|
| BoxMOT | 複数のSOTAマルチオブジェクトトラッキングアルゴリズムをプラグイン形式で利用できるPythonパッケージ |
| Deep OC-SORT | OC-SORTにRe-IDを適応的に統合したトラッキング手法。BoxMOTのクラス名は `DeepOcSort` |
| OpenPose JSON | HALPE 26パイプラインが出力するJSON形式。各フレームごとに1ファイル、人物ごとにbbox/bbox_score/キーポイントを格納 |
| track_id | BoxMOTが付与するトラッキングID。フレーム間で同一人物に同じIDが維持される |

## 3. 機能要件

### FR-1: JSONからbbox情報を読み込む [Must]

- OpenPose JSONファイル群からフレームごとに `bbox`（[x1, y1, x2, y2]）と `bbox_score`（float）を読み込む
- JSONファイル名のフレーム番号順にソートして読み込む
- **入力**: JSONディレクトリパス
- **出力**: フレームごとのbboxリスト
- **受け入れ基準**: 指定したJSONディレクトリ内の全JSONファイルのbbox情報が正しく読み込めること（テストデータでは1244フレーム）

### FR-2: 動画からフレーム画像を読み込む [Must]

- 元動画をcv2.VideoCaptureで開き、JSONと同じフレーム順でフレーム画像を取得する
- **入力**: 動画ファイルパス
- **出力**: フレーム画像（numpy.ndarray, BGR）
- **受け入れ基準**: 動画のフレーム数とJSONファイル数が一致すること。不一致の場合は警告を出力し、少ない方のフレーム数まで処理すること

### FR-3: Deep OC-SORTでトラッキングを実行する [Must]

- 各フレームのbbox情報とフレーム画像をBoxMOTの `tracker.update()` に渡し、track_idを取得する
- **入力**: bbox（ndarray shape (N, 6): [x1, y1, x2, y2, score, class]）、フレーム画像
- **出力**: tracks（ndarray shape (M, 8): [x1, y1, x2, y2, track_id, confidence, class, index]）
- **受け入れ基準**: 全フレームでエラーなくトラッキングが実行され、少なくとも1つのtrack_idが付与されること

### FR-4: トラッキング結果をコンソールに出力する [Must]

- 各フレームで検出された人物数とtrack_idを標準出力に表示する
- 全フレーム処理後に以下のサマリーを出力する:
  - 総フレーム数
  - 出現したユニークなtrack_idの一覧と各IDの出現フレーム数
  - 処理時間（秒）
- **受け入れ基準**: サマリーが正しく出力されること

### 優先順位

全機能要件（FR-1〜FR-4）がMust。MVP = 全4要件の達成。

## 4. 非機能要件

- テストスクリプトは `scripts/` ディレクトリに配置する
- 既存のパイプラインコード（`run_halpe26_pipeline.py` 等）は変更しない

## 5. 制約条件

- パッケージ管理は `uv` を使用すること
- Re-IDモデルの初回ダウンロードにインターネット接続が必要（feat-020で完了済み）

## 6. スコープ外

- 可視化動画の出力（本案件ではコンソール出力のみ）
- 室内動画でのトラッキング精度検証（feat-022で実施）
- 見切れ再同定の検証（feat-023で実施）

## 7. テストデータ

| 項目 | 値 |
|------|-----|
| 動画 | `testdata/pexels_4441000.mp4`（1920x1080, 25fps, 1244フレーム） |
| JSON | `experiments/results/feat-018-test/pexels_4441000_json/`（1244ファイル） |
| JSONフォーマット | OpenPose JSON（bbox: [x1,y1,x2,y2], bbox_score: float を含む） |
| 人物数 | 1人（全身が映る男性） |

## 8. 受け入れ基準

1. テストスクリプトが `uv run python scripts/test_boxmot_offline.py` で実行できる
2. 1244フレーム全てでエラーなくトラッキングが完了する
3. 1人の人物に対して一貫したtrack_idが付与される（IDの変化回数が少ないほど良い）
4. サマリー（ユニークID数、出現フレーム数、処理時間）がコンソールに出力される

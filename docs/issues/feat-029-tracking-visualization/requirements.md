# feat-029: トラッキング付き動画可視化 — 要求仕様書

## 1. プロジェクト概要

- **何を作るか**: stable_id付きJSONと元動画から、トラッキングIDごとに色分けしたスケルトン・BB・IDテキストを描画したMP4動画を出力するCLIスクリプト
- **なぜ作るか**: feat-026（見切れ再同定の検証）で、stable_idが正しく割り当てられているか目視検証するため。現行の可視化スクリプト（`visualize_halpe26_video.py`）はstable_id非対応で、人物の区別ができない
- **誰が使うか**: 開発者（ユーザー）がCLIから実行する
- **どこで使うか**: ローカルマシン（GPU不要、CPU処理のみ）

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| stable_id | カスタムRe-IDが割り当てた人物識別ID（int）。0以上の整数が有効なID。-1は未割当を意味する |
| BB | バウンディングボックス。人物検出領域の矩形 [x1, y1, x2, y2] |
| スケルトン | HALPE 26キーポイントを骨格線で結んだ描画 |
| stable_id付きJSON | `postprocess_reid.py` が出力したJSON。各personに `stable_id` フィールドを持つ |

## 3. 機能要求一覧

### FR-001: 指定stable_idフィルタ描画

- **機能名**: 指定stable_idのスケルトン描画
- **概要**: ユーザーが指定した1つ以上のstable_idに該当する人物のみ、スケルトン・BB・stable_idテキストを動画上に描画する
- **入力**:
  - `--video`: 元動画ファイルパス（MP4）
  - `--json-dir`: stable_id付きJSONディレクトリパス
  - `--ids`: 描画対象のstable_idリスト（1つ以上のint、スペース区切り）
  - `--out-dir`: 出力ディレクトリパス（デフォルト: `output`）
  - `--kpt-thr`: キーポイント描画の信頼度閾値（float、値域: 0.0~1.0、デフォルト: 0.3）
- **出力**: MP4動画ファイル（コーデック: `mp4v`）。指定stable_idの人物のみスケルトン・BB・stable_idテキストが描画される。他の人物は描画されない
- **受け入れ基準**:
  - `--ids 1 2` で実行した場合、stable_id=1とstable_id=2の人物のみ描画される
  - 指定stable_idが該当フレームに存在しない場合、そのフレームは元動画のみ（描画なし）で出力される
  - stable_id=-1は未割当を意味し、描画する意味がないため描画されない。`--ids` には0以上の整数を指定する（argparseが負数の `-` をオプション接頭辞と解釈するため、負数は事実上指定不可）

### FR-002: 全stable_id色分け描画

- **機能名**: 全stable_idの一括色分け描画
- **概要**: 全stable_idの人物を、IDごとに異なる色で一括描画する
- **入力**:
  - `--video`: 元動画ファイルパス（MP4）
  - `--json-dir`: stable_id付きJSONディレクトリパス
  - `--out-dir`: 出力ディレクトリパス（デフォルト: `output`）
  - `--kpt-thr`: キーポイント描画の信頼度閾値（float、デフォルト: 0.3）
  - `--ids` を省略した場合にこのモードになる
- **出力**: MP4動画ファイル。全人物がstable_idごとに色分けされて描画される
- **受け入れ基準**:
  - stable_id=1の人物とstable_id=2の人物が異なる色で描画される
  - 同一stable_idの人物は全フレームで同じ色で描画される
  - stable_id=-1の人物は未割当であるが、全体モードでは全人物の位置確認が目的のため、グレー（128, 128, 128）で描画する

### FR-003: BB描画

- **機能名**: バウンディングボックス描画
- **概要**: FR-001またはFR-002で描画対象と判定された人物に対して、BBを矩形で描画する。色はstable_idに対応する色を使用する
- **入力**: JSONの `bbox` フィールド [x1, y1, x2, y2]。4要素リストとして扱う。5要素以上の場合も先頭4要素のみ使用する
- **出力**: 動画フレーム上にBB矩形が描画される
- **受け入れ基準**:
  - BBの矩形がstable_idの色で描画される
  - 線の太さは2ピクセル

### FR-004: stable_idテキスト描画

- **機能名**: stable_idテキスト表示
- **概要**: FR-001またはFR-002で描画対象と判定された人物に対して、BB左上にstable_id番号をテキストで描画する
- **入力**: JSONの `stable_id` フィールド
- **出力**: BB左上にstable_idがテキスト表示される
- **受け入れ基準**:
  - `ID:{stable_id}` の形式でBB左上の上方に表示される（例: `ID:1`）
  - テキスト色はstable_idの色と同一
  - フォントサイズ: `cv2.FONT_HERSHEY_SIMPLEX`、スケール0.6、太さ2

### FR-005: 出力ファイル命名

- **機能名**: 出力MP4ファイル命名規則
- **概要**: 出力ファイル名はモードと入力に基づいて自動生成する
- **入力**: 動画ファイル名、モード（フィルタ/全体）
- **出力**:
  - フィルタモード: `{out-dir}/vis_tracking_{動画ステム}_ids_{id1}_{id2}.mp4`（例: `vis_tracking_camSony1_L_ids_1_2.mp4`）
  - 全体モード: `{out-dir}/vis_tracking_{動画ステム}_all.mp4`
- **受け入れ基準**:
  - 上記命名規則に従ったファイルが出力される
  - 出力ディレクトリが存在しない場合は自動作成される

### FR-006: 進捗表示

- **機能名**: 処理進捗のコンソール表示
- **概要**: 処理中のフレーム番号と総フレーム数を定期的にコンソールに表示する
- **入力**: なし
- **出力**: コンソールに `Processing frame {current}/{total} ...` を1000フレームごとに表示する。処理完了時に出力パスと処理時間を表示する
- **受け入れ基準**:
  - frame_idx=0 を含め、1000フレームごとに進捗が表示される
  - 完了時に `Done: {出力パス} ({処理時間:.1f}s)` が表示される

## 4. 非機能要求

- **パフォーマンス**: 推論処理を含まないため、動画のデコード・エンコード速度がボトルネック。具体的な速度要件は設けない
- **対応環境**: Linux、GPU不要（CPU処理のみ）
- **メモリ**: JSONは1フレームずつ読み込むため、メモリ使用量は動画フレームサイズに依存する（321Kフレームでも問題ない設計）
- **出力コーデック**: `mp4v`（MPEG-4）を使用する
- **エラー処理**: 動画ファイルが開けない場合、JSONディレクトリが存在しない場合はエラーメッセージを表示して終了する

## 5. 制約条件

- **使用ライブラリ**: OpenCV（動画読み書き・描画）、numpy（キーポイント配列のreshape・操作に必要）、標準ライブラリ
- **既存コード**: `merge_halpe26.py` の `HALPE26_SKELETON` 定義をインポートして再利用する。`draw_halpe26` と `draw_bbox` は色のカスタマイズが必要なため、本スクリプト内に描画関数を新規実装する
- **入力JSON形式**: `postprocess_reid.py` が出力するOpenPose互換JSON（`stable_id` フィールド付き）

# feat-038: pink_track_id / pink_id / track_id 動画可視化 — 要求仕様書

## 1. プロジェクト概要

### 1.1 何を作るのか

`scripts/visualize_patient_video.py`（新規）を作成する。本スクリプトは、feat-036 出力の `pink_track_id` 付き HALPE 26 JSON ディレクトリと元動画を入力とし、選択した ID 種別に基づいて BB・テキスト・キーポイント・スケルトンを動画フレームにオーバーレイした MP4 動画を出力する。

### 1.2 なぜ作るのか

feat-037 のグラフで `pink_track_id` の時系列傾向は確認できたが、「正しい BB が対象として選択されているか」「スケルトンが妥当か」は動画上で目視しなければ判断できない。また `pink_id` や `track_id` の動作確認にも同じ動画可視化が必要であるため、ID 種別を切り替え可能な汎用的な可視化スクリプトを提供する。

### 1.3 誰が使うのか

本プロジェクトの開発者。feat-033 / feat-035 / feat-036 の出力品質を目視検証するための診断ツール。

### 1.4 どこで使うのか

Linux 開発マシン（本プロジェクトの既存 ViTPose uv 環境）。コマンドラインから実行する。

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| ID 種別 | `pink_track_id` / `pink_id` / `track_id` のいずれか。CLI 引数 `--id-type` で選択する |
| ID 値 | 各 BB の選択された ID 種別のフィールド値（例: `pink_track_id=1`） |
| filter モード | 指定した ID 値を持つ BB のみ描画する。他の BB は非表示 |
| all モード | 全 BB を描画し、ID 値ごとに色分けする |
| 描画フレーム範囲 | `--draw-start` 〜 `--draw-end` で指定されたフレーム区間。この範囲内のフレームのみ BB・スケルトン等を描画する。範囲外のフレームは元動画のまま素通しする |
| 素通し | BB・スケルトン等の描画を行わず、元動画フレームをそのまま出力する |

## 3. 機能要求一覧

### FR-001: CLI インタフェース

- **コマンド**: `uv run python scripts/visualize_patient_video.py [引数]`
- **引数**:

  | 引数 | 必須 | 型 | デフォルト | 意味 |
  |------|------|----|-----------|------|
  | `--video` | 必須 | パス | - | 入力動画ファイル |
  | `--json-dir` | 必須 | パス | - | 入力 JSON ディレクトリ（`pink_track_id` / `pink_id` / `track_id` 付き） |
  | `--out-dir` | 任意 | パス | `output` | 出力ディレクトリ |
  | `--id-type` | 任意 | str | `pink_track_id` | 描画に使用する ID 種別。`pink_track_id` / `pink_id` / `track_id` |
  | `--mode` | 任意 | str | `all` | 描画モード。`filter`（指定 ID 値のみ描画）/ `all`（全 BB 色分け描画） |
  | `--filter-values` | 任意 | int リスト | `[1]` | `--mode filter` 時に描画する ID 値のリスト（例: `--filter-values 1` で `pink_track_id=1` のみ描画） |
  | `--draw-start` | 任意 | int | `0` | 描画開始フレーム（この番号以降のフレームで描画する） |
  | `--draw-end` | 任意 | int | `-1`（末尾） | 描画終了フレーム（`-1` は動画末尾まで） |
  | `--kpt-thr` | 任意 | float | `0.3` | キーポイント描画の confidence 閾値 |

- **受け入れ基準**:
  - AC-001-1: 必須引数が未指定の場合、argparse のエラーで終了コード 2
  - AC-001-2: `--id-type` に無効な値（`pink_track_id` / `pink_id` / `track_id` 以外）を指定した場合、エラーメッセージを出して終了
  - AC-001-3: `--mode` に無効な値を指定した場合、エラーで終了
  - AC-001-4: `--out-dir` が存在しない場合、自動作成する

### FR-002: 動画読み込みとフレームループ

- **概要**: 元動画を全フレーム読み込み、各フレームで対応する JSON を参照して描画を行い、MP4 動画として書き出す
- **処理**:
  1. `cv2.VideoCapture` で動画をオープン
  2. fps / width / height を取得し、`cv2.VideoWriter` で出力 MP4 を初期化
  3. フレームごとに `cap.read()` でフレームを取得
  4. 対応 JSON を `{json_stem}_{frame_idx:06d}.json` で読み込む
  5. 描画フレーム範囲内なら FR-003〜005 に基づいて描画
  6. 範囲外ならフレームをそのまま書き出す（素通し）
  7. 全フレーム処理後、`cap.release()` / `writer.release()`
- **出力ファイル名**: `vis_{id_type}_{mode}_{video_stem}.mp4`（例: `vis_pink_track_id_filter_camSony1_S.mp4`）
- **受け入れ基準**:
  - AC-002-1: 出力 MP4 のフレーム数が入力動画と一致する
  - AC-002-2: `--draw-start 100 --draw-end 200` 指定時、フレーム 0〜99 と 201〜末尾は素通し、100〜200 のみ描画される
  - AC-002-3: JSON が存在しないフレームは素通しする
  - AC-002-4: `--draw-start` が動画フレーム数以上の場合、全フレームが素通しとなる（エラーではない）
  - AC-002-5: `--draw-start > --draw-end`（`--draw-end` が `-1` でない場合）のとき、描画対象フレームがゼロになり全フレームが素通しとなる（エラーではない）

### FR-003: BB 描画

- **概要**: 各人物の BB（バウンディングボックス）を矩形として描画する
- **描画内容**:
  - 矩形: `bbox` 座標で描画、色は ID 値に応じた色パレットから選択
  - テキスト（BB 上部）: 選択した ID 種別の略称と値。略称マッピング: `pink_track_id` → `ptid`、`pink_id` → `pid`、`track_id` → `tid`（例: `ptid:1`）
  - テキスト（BB 上部、ID テキストの横）: `bbox_score`（例: `0.95`）
- **filter モード**: `--filter-values` に含まれる ID 値を持つ BB のみ描画。他は非表示
- **all モード**: 全 BB を描画。ID 値ごとに色分け
- **受け入れ基準**:
  - AC-003-1: filter モードで `--filter-values 1` 指定時、`pink_track_id=1` の BB のみ描画される
  - AC-003-2: all モードで異なる ID 値の BB が異なる色で描画される
  - AC-003-3: BB 上部に ID 値と bbox_score がテキスト表示される

### FR-004: キーポイント・スケルトン描画

- **概要**: 各人物の HALPE 26 キーポイントとスケルトンを描画する
- **描画内容**:
  - キーポイント: `pose_keypoints_2d` から 26 点を描画。confidence が `--kpt-thr` 以下の点は非表示
  - スケルトン: `merge_halpe26.HALPE26_SKELETON` の接続定義に従い、両端のキーポイントが閾値以上の場合に線を描画
  - 色は FR-003 と同じ色パレット（BB と同色）
- **filter / all モードの適用**: FR-003 と同じフィルタリングルール
- **受け入れ基準**:
  - AC-004-1: confidence が閾値以上のキーポイントが円で描画される
  - AC-004-2: スケルトンの接続線が描画される
  - AC-004-3: filter モード時、描画対象外の BB のキーポイント・スケルトンも非表示になる

### FR-005: 色パレット

- **概要**: ID 値に応じて色を決定する
- **ルール**:
  - `all` モード: ID 値ごとに HSV 色相均等分割パレットから色を割り当てる。負の ID 値（`-1`, `-2`）はグレー
  - `filter` モード: 描画対象の BB は固定色（例: 緑）。描画対象外は非表示のため色不要
- **受け入れ基準**:
  - AC-005-1: 異なる正の ID 値には異なる色が割り当てられる
  - AC-005-2: 負の ID 値（`-1`, `-2`）はグレーで描画される

### FR-006: フレーム番号オーバーレイ

- **概要**: 各フレームの左上にフレーム番号を表示する
- **描画**: 描画フレーム範囲内・外に関わらず常に表示
- **受け入れ基準**:
  - AC-006-1: 全フレームの左上にフレーム番号が表示される

### FR-007: 進捗表示・サマリ

- **概要**: 処理進捗とサマリを標準出力に表示する
- **受け入れ基準**:
  - AC-007-1: 3000 フレームごとに進捗が表示される
  - AC-007-2: 処理完了後にサマリ（フレーム数、処理時間、出力パス）が表示される

## 5. 制約条件

### 5.1 使用ライブラリ

- OpenCV（動画読み書き、描画）
- numpy（キーポイント配列操作）
- `merge_halpe26.HALPE26_SKELETON`（スケルトン接続定義、既存モジュールから import）
- 標準ライブラリ

### 5.2 変更禁止

- 既存スクリプト全て

### 5.3 データ制約

- 入力 JSON は feat-036 出力形式（`pink_track_id`, `pink_id`, `track_id`, `bbox_score`, `pose_keypoints_2d` を各 `people` 要素に含む）を想定する
- `--id-type` で指定した ID フィールドが入力 JSON に存在しない場合の振る舞い: `all` モードでは ID 値テキストが `?` と表示され、BB・スケルトンはそのまま描画される。`filter` モードではその BB は描画対象外（スキップ）となる

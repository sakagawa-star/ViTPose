# feat-044 要求仕様書: pink → blue 動画変換ツール

## 1. プロジェクト概要

### 1.1 何を作るのか

`scripts/convert_pink_to_blue_video.py` を新規作成する。入力動画の各フレームを HSV 空間で処理し、ピンク領域に該当する画素の色（H・S）を「低彩度の青」に置換した合成動画を出力する。

### 1.2 なぜ作るのか

- NDA により本物の青患者動画が入手できないため、青色対応パイプライン（feat-045 以降）の動作検証用の合成データが必要
- 既存のピンク患者動画は HSV 範囲で高精度にピンク領域を抽出できるため、ピンク → 青の置換が現実的
- Blue2.png / Blue4.png の HSV 分析結果（**同一の青病院着が照明変動により S 中央値 25–43、V 中央値 137–158 と幅広く動く**）の中間値に近づく変換を行うことで、青用検出ロジックの妥当性検証が可能になる
- 動画自体には patient identifying な情報が含まれない（ピンク患者は研究員撮影データ）ため、合成動画の取り扱いは本物の患者動画より柔軟

### 1.3 誰が使うのか

本プロジェクトの開発者（feat-045 で青用 `postprocess_blue_id.py` を検証する者）。

### 1.4 どこで使うのか

既存スクリプトと同一の実行環境（uv 環境、CPU + OpenCV）。

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| ピンク領域 | 入力フレームの HSV 空間において、`postprocess_pink_id.py` の `FIXED_HSV_RANGES` と同一範囲（3 範囲の OR）に該当する画素の集合 |
| L2 変換 | ピンク領域の H を青中心値（`target_H`、デフォルト 110）に置換、S を `S × s_scale`（デフォルト 0.35）かつ上限 `s_max`（デフォルト 80）でクリップ。V は変更なし |
| 合成動画 | 本案件の出力 MP4。入力動画と同じ解像度・FPS・フレーム数を持ち、ピンク領域のみ青に置換されている |
| 既定 HSV 範囲 | `postprocess_pink_id.py` 既存の 3 範囲 (`(0, 60, 80)-(10, 255, 255)`、`(140, 60, 80)-(159, 255, 255)`、`(160, 60, 80)-(179, 255, 255)`) |

## 3. 機能要求一覧

### FR-001: ピンク領域の HSV 抽出

- **概要**: 入力フレームの BGR 画像を HSV に変換し、既定 HSV 範囲（コード内定数 `DEFAULT_HSV_RANGES`）に該当する画素のマスクを生成する
- **入力**:
  - 入力動画（CLI `--input`、必須）
- **出力**: フレームごとの `mask: numpy.ndarray, shape=(H, W), dtype=bool`
- **処理内容**:
  1. `cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)` で HSV 変換
  2. 各 HSV 範囲ごとに `cv2.inRange` で個別マスクを生成
  3. すべての個別マスクの OR を取る
- **受け入れ基準**:
  - AC-001-1: `postprocess_pink_id.py` の `compute_pink_ratio` と同一の HSV 範囲で同一画素を「ピンク」と判定する
  - AC-001-2: ピンク領域 0% のフレーム（人物が映っていない等）でも処理がクラッシュしない（マスクが全 False になるだけ）

注記: HSV 範囲の CLI 経由カスタマイズは本案件のスコープ外とし、`DEFAULT_HSV_RANGES` 定数固定とする。範囲変更が必要になった場合は別案件で CLI 化を検討する。

### FR-002: ピンク領域の青置換

- **概要**: マスク内の画素について、H を `target_H` に、S を `min(S × s_scale, s_max)` に置換する。V は変更しない
- **入力**:
  - HSV フレーム
  - FR-001 のマスク
  - `target_H`（CLI `--target-h`、デフォルト 110）
  - `s_scale`（CLI `--s-scale`、デフォルト 0.35）
  - `s_max`（CLI `--s-max`、デフォルト 80）
- **出力**: 変換済み HSV フレーム
- **処理内容**:
  1. `hsv[mask, 0] = target_h`
  2. `hsv[mask, 1] = np.clip(hsv[mask, 1].astype(np.int32) * s_scale, 0, s_max).astype(np.uint8)`
  3. V は変更しない
- **受け入れ基準**:
  - AC-002-1: マスク内の全画素の H が `target_H` 値になる
  - AC-002-2: マスク内の S は `s_max` を超えない
  - AC-002-3: マスク内の S は元の `S × s_scale` 以下
  - AC-002-4: マスク外の画素（ピンクでない領域）は H/S/V とも変更されない
  - AC-002-5: V チャンネルは全画素で変更されない（マスク内外問わず）

### FR-003: 合成動画の出力

- **概要**: 変換済み HSV フレームを BGR に戻し、入力動画と同じ解像度・FPS・フレーム数で MP4 ファイルとして書き出す
- **入力**: 各フレームの変換済み HSV
- **出力**: 合成動画 MP4（CLI `--output` で指定、または既定パス `{input_stem}_blue.mp4`）
- **処理内容**:
  1. `cv2.cvtColor(hsv, cv2.COLOR_HSV2BGR)` で BGR に戻す
  2. `cv2.VideoWriter` (fourcc=`mp4v`) で書き出し
- **受け入れ基準**:
  - AC-003-1: 出力動画のフレーム数 = 入力動画のフレーム数
  - AC-003-2: 出力動画の幅・高さ = 入力動画の幅・高さ
  - AC-003-3: 出力動画の FPS = 入力動画の FPS
  - AC-003-4: 既定出力パスは `{出力ディレクトリ}/{入力ファイルの拡張子なし名}_blue.mp4`
  - AC-003-5: 既存の同名出力ファイルは警告なく上書きする
  - AC-003-6: 入力動画の `fps <= 0` または `width <= 0` または `height <= 0` の場合、標準エラーにメッセージを出力して exit code 1 で終了する

### FR-004: CLI 引数

- **概要**: 入力動画パス・出力ディレクトリ・HSV 変換パラメータを CLI で指定可能にする
- **入力**:
  - `--input` (str, 必須): 入力動画パス
  - `--out-dir` (str, デフォルト `output`): 出力ディレクトリ
  - `--target-h` (int, デフォルト 110): 置換後 H 値、値域 [0, 179]
  - `--s-scale` (float, デフォルト 0.35): S 圧縮係数、値域 [0.0, 1.0]
  - `--s-max` (int, デフォルト 80): S 上限値、値域 [0, 255]
- **出力**: 上記パラメータがパース済みの `args` オブジェクト
- **受け入れ基準**:
  - AC-004-1: `--help` で全 5 引数が表示される
  - AC-004-2: `--target-h 100` 指定時、出力動画のピンク変換領域の H 値が 100 になる
  - AC-004-3: `--s-scale 0.5` 指定時、変換後 S が `元 S × 0.5` 以下（`s_max` クリップを除く）
  - AC-004-4: `--s-max 30` 指定時、変換後 S が 30 を超えない
  - AC-004-5: 必須引数 `--input` が省略された場合、argparse の標準エラーで終了する
  - AC-004-6: 値域外の引数（`--target-h 200` / `--target-h -1` / `--s-scale 1.5` / `--s-scale -0.1` / `--s-max 300` / `--s-max -1`）が指定された場合、argparse の標準仕様によりメッセージ出力 + exit code 2 で終了する（uint8 ラップによる不定動作を防ぐ）

### FR-005: 進捗表示・サマリ

- **概要**: 処理中の進捗を一定間隔で表示し、終了時にサマリを出力する
- **入力**: なし（内部状態）
- **出力**: 標準出力
- **処理内容**:
  1. 開始時に入力動画情報（パス、フレーム数、FPS、解像度）を表示
  2. 3000 フレームごとに `Processing frame N/total (P%)` を表示
  3. 終了時に `Total frames: N` / `Processing time: T sec (F fps)` / `Output: path` を表示
  4. 全フレームを通したピンク変換画素の累計数（または平均 ratio）を 1 行で表示
- **受け入れ基準**:
  - AC-005-1: 開始時表示が `Video: ... ({total_frames} frames, {fps} fps, {width}x{height})` 形式
  - AC-005-2: 進捗が 3000 フレーム間隔（フレーム 0 を含むタイミング）で表示される
  - AC-005-3: 終了時に `Total frames` / `Processing time` / `Output` の 3 行と平均ピンク比率が表示される

## 4. 非機能要求

### NFR-001: パフォーマンス

- camSony1_S.mp4（900 フレーム、640x480 程度）で **30 秒以内** に処理完了する
- camSony1_L.mp4（321K フレーム、1920x1080）の処理時間目標は別途実測ベースで決定する（本案件では camSony1_S での実測のみを Must とし、L での性能目標値は実測値を確認次第 README に追記、L 適用判断は実測後に行う）
  - 比較参考値: 同程度の per-frame 処理コストを持つ `visualize_patient_video.py` の bug-003 修正後実測 ≈ 4.8 秒 / 1397 frames ≈ 290 fps（描画あり）。本スクリプトは描画なし HSV 変換のみのため、同等以上の fps を期待

### NFR-002: 対応環境

- Python 3.10.16、uv 環境、CPU 実行、OpenCV + numpy のみ。GPU 不要

### NFR-003: 出力品質

- 出力動画は OpenCV / VLC / ffmpeg などの標準的な MP4 デコーダで再生可能であること
- 元動画と比較して、ピンク以外の領域に視覚的な劣化（圧縮ノイズを除く）が発生しないこと

## 5. 制約条件

### 5.1 使用必須のライブラリ

- 既存依存のみ（OpenCV、numpy）。新規ライブラリの導入は行わない

### 5.2 追加禁止

- L1 / L3 レベルの変換実装
- 患者シルエット検出・境界処理
- 音声トラックの保持（OpenCV の VideoWriter は音声非対応）
- HSV 範囲は `DEFAULT_HSV_RANGES` 定数固定（FR-001 注記参照）。本案件では CLI 化しない

### 5.3 ファイル命名規約

- 出力ファイル名: `{出力ディレクトリ}/{入力ファイルの拡張子なし名}_blue.mp4`
- 例: `--input testdata/camSony1_S.mp4 --out-dir /tmp/test` ⇒ `/tmp/test/camSony1_S_blue.mp4`

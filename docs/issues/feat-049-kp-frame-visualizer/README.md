# feat-049: keypoint-rect モード単体・全フレーム可視化ツール

## ステータス

Open

## 概要

`postprocess_pink_id.py --roi-mode keypoint-rect` の出力 JSON ディレクトリと元動画を入力に、**全フレームを 1 フレーム 1 枚ずつ PNG として描画**するスクリプトを新規作成する。各 PNG には kp モードの選択結果（人物 BB、keypoint-rect ROI、胴体 4 キーポイント、pink_ratio、状態）を描画し、kp モード単体の挙動をフレーム単位で目視検証できるようにする。

## 背景

feat-046 / feat-047 / feat-048 を経て keypoint-rect モードの挙動検証を進めているが、ユーザーは個別フレーム単位での信頼性確認段階にある。feat-048（不一致フレーム可視化）は bb モードとの比較が前提のため、kp モード単体の挙動（特に不一致でないフレームでの ROI 構築や pink_ratio 値）を確認するには不適切。

集計グラフ（feat-040 plot_pink_ratio_timeline.py 等）は個別フレームの信頼性が確立してから初めて意味を持つため、現段階では「全 900 フレームを 1 枚ずつ目視する」運用が必要。

## 関連案件

- 親: feat-046（keypoint-rect ROI 実装、本案件で出力 JSON を可視化）
- 兄: feat-048（不一致フレーム可視化、本案件は kp モード単体可視化として独立）
- 後続: bug-004（feat-046 ROI 品質ガード強化）— 本案件の可視化で観察された問題（例: 片側 2 点 ROI、退化矩形）を根拠に着手

## 用途

- camSony1_S 全 900 フレームを順に目視し、各フレームの ROI 構築・pink_ratio 算出・キーポイント信頼度を確認
- bug-004 / feat-046 改修の必要性を裏付ける具体事例の収集
- 既存スクリプト（feat-048 等）が個別ケースで正しく描画されているかの上位確認

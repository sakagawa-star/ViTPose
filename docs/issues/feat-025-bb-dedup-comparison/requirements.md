# feat-025: BB重複除去方式の比較（案A vs 案E） — 要求仕様書

## 1. プロジェクト概要

- **何を作るか**: BB重複検出時の2つの除去方式（案A: 外接矩形再推定、案E: スコア最大BB選択）の精度を比較するCLIスクリプト
- **なぜ作るか**: feat-024でYOLO11x（mAP 54.7）でもBB重複が残存することが判明。重複除去の後処理が必要だが、方式によりキーポイント精度が異なる。案Aは精度が高いが処理コストが大きく、案Eはシンプルだが部分BBのキーポイント精度が未知。どちらを採用するか判断するために、複数の動画で定量比較を行う
- **誰が使うか**: 開発者（調査用）
- **どこで使うか**: RTX 5060 Ti搭載マシン、CUDA環境

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| BB重複 | 同一人物に対して複数のBBが出力される問題。パターン1（正しいBB + 小さなBB）とパターン2（体の部位ごとのBB）がある |
| 案A（外接矩形再推定） | 重複BBの外接矩形（union BB）を作成し、その1つのBBでポーズ推定をやり直す方式 |
| 案E（スコア最大BB選択） | 重複BBのうちbbox scoreが最大のBBのキーポイントをそのまま採用する方式 |
| OKS | Object Keypoint Similarity。COCO標準のキーポイント類似度指標。0〜1で、1が完全一致。0.5以上が同一人物マッチの基準 |
| 重複判定 | 同一人物に対して複数のBBが出力されたことを示す判定。詳細な判定ロジックはセクション5の制約条件を参照 |

## 3. 機能要求一覧

### FR-001: 案A/E比較CLIスクリプトの作成

- **機能名**: BB重複除去方式の精度比較スクリプト
- **概要**: 動画を入力として、フレームごとにYOLO11xで検出し、重複検出フレームに対して案Aと案Eの両方でキーポイントを推定する。案Aの結果を基準として、案Eとの間のOKSを計算し、統計を出力する
- **入力**:
  - `--video`: 入力動画パス（必須）
  - `--device`: 推論デバイス（デフォルト`cuda:0`）
  - `--bbox-thr`: 検出スコア閾値（デフォルト0.3）
  - `--oks-thr`: 重複判定のOKS閾値（デフォルト0.5）
- **出力**: 標準出力に以下の統計情報を表示する
  - 総フレーム数、重複検出フレーム数（割合）
  - 案A vs 案EのOKS統計（平均、中央値、最小、最大）
  - OKS分布（以下の閾値ごとの件数: >0.50, >0.75, >0.90, >0.95）
- **受け入れ基準**:
  1. `testdata/cam05520129.mp4`で実行が完了し、統計情報が出力されること
  2. 重複検出フレームがない動画では「重複なし」と表示して正常終了すること
  3. 案Aの結果（外接矩形でのキーポイント）と案Eの結果（スコア最大BBのキーポイント）の間のOKSが正しく計算されること

## 4. 非機能要求

- **パフォーマンス**: 処理速度の要件なし（調査用スクリプトのため）
- **対応環境**: RTX 5060 Ti + CUDA

## 5. 制約条件

- **使用必須**: YOLO11x（ultralytics 8.4.33）を検出器として使用する
- **コード変更方針**: 既存スクリプト（`run_halpe26_pipeline*.py`、`merge_halpe26.py`）を変更しない。新規スクリプトを`scripts/`に作成する
- **重複判定ロジック**: 同一フレーム内で人物が2人以上検出され、かつキーポイントペアのOKS > `--oks-thr`のペアが存在する場合を「重複検出」とする。OKS <= `--oks-thr`のペアは本当の2人と見なし、除去対象としない

# feat-025: BB重複除去方式の比較（案A vs 案E） — 要求仕様書

## 1. プロジェクト概要

- **何を作るか**: BB重複検出時の2つの除去方式（案A: 外接矩形再推定、案E: スコア最大BB選択）の精度を比較するCLIスクリプト。可視化動画・OpenPose JSON・OKS統計の3種を出力する
- **なぜ作るか**: feat-024でYOLO11x（mAP 54.7）でもBB重複が残存することが判明。重複除去の後処理が必要だが、案Aの結果が本当に正しいか目視確認が必要であり、また案Eとの精度差を定量評価する必要がある
- **誰が使うか**: 開発者（調査用）
- **どこで使うか**: RTX 5060 Ti搭載マシン、CUDA環境

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| BB重複 | 同一人物に対して複数のBBが出力される問題。パターン1（正しいBB + 小さなBB）とパターン2（体の部位ごとのBB）がある |
| 案A（外接矩形再推定） | 重複BBの外接矩形（union BB）を作成し、その1つのBBでポーズ推定をやり直す方式 |
| 案E（スコア最大BB選択） | 重複BBのうちbbox scoreが最大のBBのキーポイントをそのまま採用する方式 |
| OKS | Object Keypoint Similarity。COCO標準のキーポイント類似度指標。0〜1で、1が完全一致 |
| 重複判定 | 同一人物に対して複数のBBが出力されたことを示す判定。詳細な判定ロジックはセクション5の制約条件を参照 |

## 3. 機能要求一覧

### FR-001: 案A/E比較CLIスクリプトの作成

- **機能名**: BB重複除去方式の精度比較スクリプト
- **概要**: 動画を入力として、フレームごとにYOLO11xで検出し、重複検出フレームに対して案Aと案Eの両方でキーポイントを推定する。案A・案Eそれぞれの可視化動画とOpenPose JSONを出力し、さらに案Aを基準とした案EとのOKS統計を表示する
- **入力**:
  - `--video`: 入力動画パス（必須）
  - `--out-dir`: 出力ディレクトリ（デフォルト`output`）
  - `--device`: 推論デバイス（デフォルト`cuda:0`）
  - `--bbox-thr`: 検出スコア閾値（デフォルト0.3）
  - `--oks-thr`: 重複判定のOKS閾値（デフォルト0.5）
  - `--kpt-thr`: キーポイント描画閾値（デフォルト0.3）
- **出力**:
  1. 案Aの可視化動画: `{out-dir}/vis_dedup_a_{動画名}.mp4`（BB + スケルトン描画）
  2. 案Eの可視化動画: `{out-dir}/vis_dedup_e_{動画名}.mp4`（BB + スケルトン描画）
  3. 案AのOpenPose JSON: `{out-dir}/{動画stem}_dedup_a_json/` ディレクトリ
  4. 案EのOpenPose JSON: `{out-dir}/{動画stem}_dedup_e_json/` ディレクトリ
  5. 標準出力にOKS統計情報（平均、中央値、最小、最大、閾値 >0.50 / >0.75 / >0.90 / >0.95 ごとの件数と割合）
- **受け入れ基準**:
  1. `testdata/cam05520125.mp4`（BB重複が確認済みの動画）で実行が完了し、案A・案Eの可視化動画・JSONが出力されること
  2. 重複検出フレームがない動画では重複グループなしの旨を表示して正常終了すること（可視化動画・JSONは重複なしの結果で出力される）
  3. 案Aの結果と案Eの結果の間のOKSが0.0〜1.0の範囲内であり、統計値が目視で妥当であること
  4. 可視化動画で案A・案Eのキーポイント位置を目視比較できること

### FR-002: YOLO11x + 案A重複除去パイプライン

- **機能名**: BB重複除去（案A）付き2Dキーポイント推定パイプライン
- **概要**: 既存の `run_halpe26_pipeline_yolo11.py` に案A（外接矩形再推定）の重複除去ロジックを組み込む。`compare_dedup_methods.py` から案Aのロジック（`method_a`、`build_dedup_groups`、`compute_oks_mutual`、`HALPE26_SIGMAS`）を移植する
- **変更対象**: `scripts/run_halpe26_pipeline_yolo11.py`
- **入力**: 既存CLI引数に加え、以下を追加:
  - `--oks-thr`: 重複判定のOKS閾値（float、デフォルト0.5）。`compare_dedup_methods.py` と同一のデフォルト値
- **処理フロー変更**:
  1. 既存: YOLO11x検出 → `inference_top_down_pose_model`内部でbbox_thrフィルタ → ポーズ推定 → 出力
  2. 変更後: YOLO11x検出 → 事前にbbox_thrフィルタ → `bbox_thr=None`でポーズ推定 → OKSで重複検出 → 重複グループに案Aを適用 → 出力
  3. bbox_thrフィルタリング方式を`compare_dedup_methods.py`と同一の事前フィルタ方式に変更する。これにより`person_results`と推論結果のインデックスが1対1で対応する
- **出力**: 既存と同じ形式（可視化動画 + OpenPose JSON）。重複BBは案Aで除去された結果のみ出力する。案Eの結果は出力しない
- **受け入れ基準**:
  1. BB重複が確認済みの動画（`testdata/cam05520125.mp4`）で実行し、重複除去された結果が出力されること
  2. 重複が発生しない動画では既存と同一の結果が出力されること（重複除去ロジックが空振りするだけ）
  3. `--oks-thr` 未指定時、デフォルト0.5で動作すること
  4. 重複除去ロジック（`compute_oks_mutual`、`build_dedup_groups`、`method_a`）が`compare_dedup_methods.py`と同一の関数ロジック（制御フロー、演算、戻り値）であることをコードレビューで確認する。コメント・型ヒント・フォーマットの差異は許容する

## 4. 非機能要求

- **パフォーマンス**: FR-001は処理速度の要件なし（調査用スクリプトのため）。FR-002は重複除去による追加処理があるが、重複フレームのみ再推定が発生するため、非重複フレームでは既存と同等の速度
- **対応環境**: RTX 5060 Ti + CUDA

## 5. 制約条件

- **使用必須**: YOLO11x（ultralytics 8.4.33）を検出器として使用する
- **コード変更方針**: FR-001は既存スクリプトを変更せず新規スクリプトを作成する。FR-002は`run_halpe26_pipeline_yolo11.py`を変更する
- **bbox_thrフィルタリング**: `process_yolo11_results`で取得したBBのうち、bbox score >= `--bbox-thr`のBBのみを使用する
- **重複判定ロジック**: 全BBのキーポイントを推定した後に、キーポイント間のOKSで重複を判定する。同一フレーム内で人物が2人以上検出され、かつキーポイントペアのOKS > `--oks-thr`のペアが存在する場合を「重複検出」とする。OKS <= `--oks-thr`のペアは本当の2人と見なし、除去対象としない。重複判定OKSは両者のconfidence > 0.3の共通キーポイントで計算し、areaは各ペアのBBのうち面積`(x2-x1)*(y2-y1)`が大きい方を使用する
- **OKS confidence閾値**: OKS計算時のconfidence閾値はbbox_thrと同値の0.3固定とする
- **案A vs 案EのOKS計算**: 案Aのconfidence > 0.3のキーポイントを基準とし、案E側はconfidenceに関係なく使用する
- **非重複フレームの扱い**: 重複が発生しないフレームでは、案A・案Eともに通常の検出結果（全BBでのキーポイント）をそのまま出力する。重複フレームのみ案A・案Eで結果が異なる

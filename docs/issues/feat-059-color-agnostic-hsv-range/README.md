# feat-059: analyze_clothing_color.py の色非依存レンジ提案（有彩色・白・黒・灰対応）

## ステータス
- Open（要求仕様書・機能設計書 作成中 → レビュー待ち）

## 概要
`scripts/analyze_clothing_color.py` は「服の静止画を入力すると、その服の色を捕まえる HSV レンジ（`postprocess_pink_id.py --hsv-config` 互換）を提案する」ツールである。しかし現状は**有彩色（ピンク・赤・青など色相で区別できる色）専用**であり、白い服を入力しても対象を追跡できる特徴量（レンジ）を出せない。

本案件は、入力された服が**有彩色でも無彩色（白・黒・灰）でも、その色を捕まえるレンジを自動で提案できる**ようにツールを改修する。

## 背景
- E0049 対象（白い服）の静止画で本ツールを実行したところ、`proposed mask` がほぼ黒・提案レンジが色相5〜50に散らばる無意味なものとなり、対象を追える特徴量を出せなかった。
- 原因は提案ロジック（`propose_ranges_from_chroma` / `extract_chroma_hsv`）が「低彩度画素を捨て、残った有彩色画素の色相からレンジを作る」構造で、白（彩度がほぼ0）では使える画素がほぼ残らないため。
- 手作業で白レンジ `((0,0,150),(179,40,255))` を当てると E0049 の胴体ROIで比率0.83〜0.98と安定して捕まることを確認済み（使い捨て計測）。よって HSV のパラメーター（レンジ値）次第で白も表せる。ツール側が自動でそのレンジを導けないことが問題。

## 採用方針（消去法で方式B）
色を「有彩色／白／黒／灰」に**分類してから**種類別ロジックで提案する方式（方式A）は、有彩色・白・黒を信頼性高く区別する閾値を決められないため却下。分類せず ROI の主要画素クラスタを HSV 空間で直接 percentile で囲む方式（方式B）を**消去法で**採用する（方式Bが優れているからではなく、方式Aの前提が成り立たないため）。

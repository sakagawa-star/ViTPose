# feat-023: YOLOX-l検出器検証 — 要求仕様書

## 1. プロジェクト概要

- **何を作るか**: 現在のFaster R-CNN R50-FPNをYOLOX-lに差し替えた検証用パイプラインスクリプト
- **なぜ作るか**: Faster R-CNN R50-FPN（COCO訓練、mAP 37.4）が臥位の対象を正しく検出できず、1つの体に3個のBBが重複する問題が発生している（feat-022で判明）。より高精度なYOLOX-l（mAP 49.4）で臥位人物の検出が改善するか検証する
- **誰が使うか**: 開発者（検証用）
- **どこで使うか**: RTX 5060 Ti搭載マシン、CUDA環境

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| YOLOX-l | YOLOXのLargeモデル。COCO val2017でmAP 49.4 |
| Faster R-CNN R50-FPN | 現在使用中の検出器。COCO val2017でmAP 37.4 |
| BB | バウンディングボックス（人物検出の矩形領域） |
| BB重複問題 | 臥位の人物に対して1つの体に複数のBBが出力される問題 |
| 検証用パイプライン | `scripts/run_halpe26_pipeline.py` のコピーに検出器変更を加えたスクリプト |

## 3. 機能要求一覧

### FR-001: YOLOX-lチェックポイントのダウンロード

- **機能名**: YOLOX-lの事前学習済みモデルのダウンロード
- **概要**: MMDetection公式のYOLOX-l COCO事前学習済みチェックポイントを`checkpoints/`にダウンロードする
- **入力**: なし
- **出力**: `checkpoints/yolox_l_8x8_300e_coco_20211126_140236-d3bd2b23.pth`
- **受け入れ基準**: ファイルが存在し、MMDetのinit_detectorで読み込みエラーが出ないこと

### FR-002: 検証用パイプラインスクリプトの作成

- **機能名**: YOLOX-l検出器を使用する検証用パイプラインスクリプト
- **概要**: `scripts/run_halpe26_pipeline.py` をコピーし、検出器をYOLOX-lに差し替えたスクリプトを作成する
- **入力**: `--video`（動画パス）、`--out-dir`（出力ディレクトリ）、`--device`、`--mode`、`--kpt-thr`、`--profile`（既存パイプラインと同じ引数）に加え、`--bbox-thr`（検出スコア閾値、デフォルト0.3）
- **出力**: 既存パイプラインと同じ出力（可視化動画、OpenPose JSON）
- **受け入れ基準**:
  1. `testdata/camSony1.mp4`（室内動画）で実行が完了し、可視化動画が出力されること
  2. 検出器部分のみが変更され、ポーズ推定・結合・出力ロジックは既存パイプラインと同一であること
  3. `--bbox-thr 0.5` で実行した場合、`--bbox-thr 0.3` よりBB数が減ること（フィルタリングが機能していること）

### FR-003: 室内動画での検出精度の比較確認

- **機能名**: 検出結果の目視比較
- **概要**: 室内動画（`testdata/camSony1.mp4`）に対してYOLOX-l版パイプラインを実行し、BB描画結果を目視で確認する
- **入力**: `testdata/camSony1.mp4`
- **出力**: BB描画付き可視化動画
- **受け入れ基準**: 出力動画が生成され、ユーザーがBBの重複問題の改善有無を目視で判断できること

## 4. 非機能要求

- **パフォーマンス**: 処理速度の要件なし（検証用スクリプトのため）。ただし`--profile`で速度を計測可能であること
- **対応環境**: RTX 5060 Ti + CUDA、MMDet 2.28.2で動作すること

## 5. 制約条件

- **使用必須**: MMDetection 2.28.2に同梱のYOLOX実装を使用する（外部のYOLOXリポジトリは使わない）
- **コード変更方針**: `scripts/run_halpe26_pipeline.py` および `scripts/merge_halpe26.py` を直接変更しない。コピーを作成して検出器部分のみ差し替える
- **チェックポイント配置先**: `checkpoints/` ディレクトリ

## 6. 優先順位

| ID | 優先度 | 備考 |
|----|--------|------|
| FR-001 | Must | チェックポイントがないと検証不可 |
| FR-002 | Must | 検証用スクリプトの本体 |
| FR-003 | Must | 検証の目的そのもの |

MVP: FR-001〜FR-003すべて。

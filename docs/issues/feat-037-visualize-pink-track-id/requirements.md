# feat-037: pink_track_id 時系列可視化グラフ — 要求仕様書

## 1. プロジェクト概要

### 1.1 何を作るのか

`scripts/plot_pink_track_timeline.py`（新規）を作成する。本スクリプトは、feat-036 `postprocess_patient_id.py` が出力した `pink_track_id` 付き HALPE 26 JSON ディレクトリを入力とし、時系列グラフ（5 パネル構成の PNG 画像 1 枚）を出力する。

### 1.2 なぜ作るのか

feat-036 で `pink_track_id` の付与が完了したが、コードがエラーなく動作したことを確認しただけで、出力の正しさは未検証である。`pink_track_id` が時間軸に沿って妥当な振る舞いをしているか（対象が一貫して追跡されているか、不自然な切り替わりがないか等）を目視で判断するためのグラフが必要である。

### 1.3 誰が使うのか

本プロジェクトの開発者。feat-036 の出力品質を検証し、問題があれば原因を特定するための診断ツールとして使用する。

### 1.4 どこで使うのか

Linux 開発マシン（本プロジェクトの既存 ViTPose uv 環境）。コマンドラインから実行する。動画ファイルは参照せず、JSON のみで完結する。

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| `pink_track_id` | feat-036 が各 BB に付与する `int` フィールド。`1`=対象、`-1`=非対象、`-2`=重複 BB |
| `pink_id` | feat-033 が各 BB に付与する `int` フィールド。`1`=そのフレームで色的に対象と判定、`-1`=それ以外 |
| `track_id` | feat-035 が各 BB に付与する `int` フィールド。Deep OC-SORT の発番 ID。`-1`=マッチなし、`>=1`=有効 |
| `bbox_score` | YOLO 検出スコア（`float`） |
| パネル | 1 枚の PNG 画像内のサブプロット。本案件では 5 パネルを縦に配置する |

## 3. 機能要求一覧

### FR-001: 入力 JSON 読み込み

- **概要**: `--json-dir` 配下の全 JSON ファイルを読み込み、フレームごとの `people` 配列からグラフに必要なデータを抽出する
- **入力**: `json_dir: str`
- **抽出対象フィールド**: 各 `people[*]` の `pink_track_id`, `pink_id`, `track_id`, `bbox_score`
- **処理**: feat-035/036 と同じ `load_json_frames` パターン（`_(\d{6})\.json$` 正規表現、`JSONDecodeError` フォールバック、0 件時 `sys.exit(1)`）
- **受け入れ基準**:
  - AC-001-1: 命名規約に合致する全 JSON を読み込み、フレーム番号昇順でデータを抽出する
  - AC-001-2: JSON 0 件時は ERROR を出し終了コード 1

### FR-002: パネル 1 — `pink_track_id=1` の有無（二値タイムライン）

- **概要**: 各フレームで `pink_track_id=1` の BB が存在するか（1）しないか（0）を二値で描画する
- **描画**: X 軸=フレーム番号、Y 軸=0 or 1。塗りつぶし（fill_between 等）で視覚的に区間を示す
- **受け入れ基準**:
  - AC-002-1: `pink_track_id=1` が存在するフレームは 1、存在しないフレームは 0 で描画される
  - AC-002-2: 対象がいないフレーム区間（=0）が視覚的に識別できる

### FR-003: パネル 2 — BB 数の内訳（`pink_track_id` 値別）

- **概要**: 各フレームの BB 数を `pink_track_id` 値別（`1`, `-1`, `-2`）に集計し、描画する
- **描画**: X 軸=フレーム番号、Y 軸=BB 数。色分けして 3 系列を描画する（積み上げ or 重ね描き）
- **受け入れ基準**:
  - AC-003-1: 各フレームで `pink_track_id=1`, `-1`, `-2` の BB 数がそれぞれ識別できる
  - AC-003-2: 凡例が表示される

### FR-004: パネル 3 — `pink_track_id=1` BB の `track_id` 値の推移

- **概要**: 各フレームで `pink_track_id=1` の BB が持つ `track_id` の値をプロットする。対象の `track_id` がいつ切り替わるかを視覚的に確認する
- **描画**: X 軸=フレーム番号、Y 軸=`track_id` 値。散布図またはステップ折れ線。`pink_track_id=1` の BB がないフレームはプロットしない（欠損として扱う）
- **`pink_track_id=1` BB が存在するフレームでの取得**: そのフレームの `pink_track_id=1` BB の `track_id` を取得する（要求 E により 1 フレーム最大 1 つ）
- **受け入れ基準**:
  - AC-004-1: `track_id` の切り替わり（例: `2` → `7`）がグラフ上で視覚的に確認できる
  - AC-004-2: `pink_track_id=1` が存在しないフレームには点がプロットされない
  - AC-004-3: `track_id=-1` の場合もそのまま `-1` としてプロットする（`pink_id=1` による直接判定で `pink_track_id=1` が付与されたが、Deep OC-SORT が track を割り当てられなかったケース）

### FR-005: パネル 4 — `pink_track_id=1` BB の `bbox_score` の推移

- **概要**: 各フレームで `pink_track_id=1` の BB の `bbox_score` をプロットする
- **描画**: X 軸=フレーム番号、Y 軸=`bbox_score`（0.0〜1.0）。折れ線または散布図。`pink_track_id=1` がないフレームはプロットしない
- **受け入れ基準**:
  - AC-005-1: `bbox_score` の低下傾向や異常値がグラフ上で視覚的に確認できる
  - AC-005-2: `pink_track_id=1` が存在しないフレームには点がプロットされない

### FR-006: パネル 5 — `pink_id=1` の有無（二値タイムライン）

- **概要**: 各フレームで `pink_id=1` の BB が存在するか（1）しないか（0）を二値で描画する。パネル 1（`pink_track_id=1` の有無）と比較することで、`track_id` 拡張がどの区間で効いているかを目視確認する
- **描画**: X 軸=フレーム番号、Y 軸=0 or 1。パネル 1 と同じ描画形式で色を変える
- **受け入れ基準**:
  - AC-006-1: パネル 1 と比較して、パネル 5 が 0 でパネル 1 が 1 の区間が「track_id 拡張が効いている区間」として視覚的に識別できる
  - AC-006-2: パネル 1 とパネル 5 の X 軸が揃っている（`sharex`）

### FR-007: グラフ出力

- **概要**: 5 パネルを縦に配置した 1 枚の PNG 画像を出力する
- **レイアウト**: 5 行 1 列のサブプロット。X 軸を共有（`sharex=True`）。上から パネル 1〜5 の順
- **画像サイズ**: 横 16 インチ × 縦 12 インチ程度（5 パネルが視認可能なサイズ）
- **解像度**: 150 dpi
- **出力先**: CLI 引数 `--out-path` で指定。デフォルトなし（必須引数）
- **受け入れ基準**:
  - AC-007-1: 指定パスに PNG ファイルが出力される
  - AC-007-2: 5 パネルが縦に配置され、X 軸が共有されている
  - AC-007-3: タイトルに入力 JSON ディレクトリ名またはフレーム数が含まれる

### FR-008: CLI インタフェース

- **コマンド**: `uv run python scripts/plot_pink_track_timeline.py [引数]`
- **引数**:

  | 引数 | 必須 | 型 | デフォルト | 意味 |
  |------|------|----|-----------|------|
  | `--json-dir` | 必須 | パス | - | 入力 JSON ディレクトリ（`pink_track_id` 付与済み） |
  | `--out-path` | 必須 | パス | - | 出力 PNG ファイルパス |

- **受け入れ基準**:
  - AC-008-1: 必須引数が未指定の場合、argparse のエラーメッセージを表示して終了コード 2
  - AC-008-2: 出力先ディレクトリが存在しない場合、自動作成する

## 4. 非機能要求

### NFR-001: パフォーマンス

- camSony1_S（900 フレーム）: 数秒以内で完了
- camSony1_L（321K フレーム）: JSON 読み込みがボトルネック。feat-036 実績（58.5 秒で読み込み + 処理）と同等以内を目安とする。matplotlib の描画は 321K 点のプロットで数十秒かかる可能性があるが、1 回限りの診断用途のため許容する

### NFR-002: 対応環境

- OS: Linux（Ubuntu）
- Python: 3.10.16
- パッケージ管理: uv（`uv run python` 経由で実行）
- matplotlib: 既存 uv 環境に含まれていること（なければ `uv add matplotlib` で追加）

## 5. 制約条件

### 5.1 使用ライブラリ

- matplotlib（グラフ描画）
- 標準ライブラリ（`argparse`, `json`, `os`, `re`, `sys`, `pathlib`）

### 5.2 使用禁止

- OpenCV（動画不要）
- numpy（matplotlib が内部で使うが、スクリプト側で明示的に import する必要がなければ不使用）

### 5.3 変更禁止

- 既存スクリプト全て（`postprocess_patient_id.py` 含む）

### 5.4 データ制約

- 入力 JSON は feat-036 `postprocess_patient_id.py` の出力形式（`pink_track_id`, `pink_id`, `track_id`, `bbox_score` を各 `people` 要素に含む）

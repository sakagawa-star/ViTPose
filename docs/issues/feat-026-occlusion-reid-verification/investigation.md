# feat-026: 見切れ再同定の検証 — 調査記録

## イテレーション1 (2026-04-07)

### 1.1 不具合の特定

- **現在の動作**: 画面中央の対象（stable_id=1、bbox中心x≈330）の前を別の人物が横切ると、横切り以降stable_id=1の追跡が途切れる。最大の消失区間はフレーム6856→82583（75,727フレーム≒42分間）。Deep OC-SORTとカスタムRe-IDの両方が復帰に失敗している
- **期待する動作**: 横切りによる一時的な遮蔽の後、同一人物（対象）に同じstable_id=1が再割り当てされること
- **再現手順**:
  ```bash
  uv run python scripts/visualize_tracking.py \
    --video experiments/input/camSony1_L.mp4 \
    --json-dir experiments/results/camSony1_L_reid_json/ \
    --out-dir experiments/results/feat-026-vis/ \
    --ids 1
  ```
  生成された動画のフレーム6300-6900付近を確認する

### 1.2 原因分析

#### 事象の時系列

| フレーム | stable_id=1の状態 | stable_id=19の状態 | 備考 |
|---------|------------------|-------------------|------|
| 0-6300 | 画面中央 center_x≈330 | frame 3168から画面左端で出現 | 正常 |
| 6377 | center_x=432 (右方向へ急移動) | 画面中央 | **ここでBBが横切り人物に引きずられ始める** |
| 6385 | center_x=583 | 画面中央 | BBが右方向へ移動中 |
| 6391 | center_x=787 | 画面中央 | 対象位置から完全に離脱 |
| 6840 | bbox=[646,23,957,454] (画面右端) | bbox=[217,176,450,448] (画面中央) | sid=1は既に横切り人物のBBを追跡している |
| 6841-6848 | 消失/断続的出現 | 画面中央で安定 | 横切り人物が画面外へ退出中 |
| 6856 | 完全消失 | 画面中央で安定 | **42分間の消失開始** |
| 6857-82582 | 不在 | frame 66536まで安定 | 対象はsid=19として追跡されている可能性 |
| 82583 | bbox=[1,368,52,453] (画面左端) で復帰 | - | 別の人物検出で復帰した可能性 |

#### 原因箇所

**根本原因: Deep OC-SORTのtrack_id乗っ取り（フレーム6377付近）**

横切り人物が対象の前を通過する際、Deep OC-SORTが対象のtrack_idを横切り人物のBBに紐付けてしまう（IDスイッチ）。これにより:

1. **Deep OC-SORT側**: 対象のtrack_idが横切り人物に付与される。横切り人物が画面外に出ると、そのtrack_idも消失する。対象は画面中央に残っているが、新しいtrack_id（→stable_id=19が割り当てられている）で追跡される
2. **カスタムRe-ID側**: stable_id=1の消失後、次に出現した新track_idにRe-IDマッチングが試みられるが、以下の理由で失敗する:
   - 横切り人物のBBが対象のBBを遮蔽している間、stable_id=1の色ヒストグラム・キーポイント特徴が横切り人物の外見で上書きされる
   - 消失時点のstable_id=1の特徴量が対象ではなく横切り人物のものになっているため、対象の新track_idとマッチしない
   - stable_id=19が既にアクティブなため、対象の新track_idはsid=19として追跡継続される（Re-IDのマッチング対象は`_disappeared`のみで、アクティブなstable_idとは比較しない）

#### 根本原因 or 表面的原因

**根本原因**である。Deep OC-SORTのIDスイッチは、遮蔽時にIoUベースのBBアソシエーションが横切り人物のBBを誤って既存trackに紐付けることで発生する。カスタムRe-IDの失敗は、IDスイッチの結果として特徴量が汚染されたことによる二次的な問題。

### 1.3 問題の分類

この問題は**カスタムRe-IDの修正だけでは解決できない**。原因の構造:

```
Deep OC-SORT IDスイッチ（track_id乗っ取り）
  → stable_id=1の特徴量が横切り人物で汚染
    → Re-IDマッチング失敗
      → stable_id=1が42分間消失
```

改善の方向性（候補、未検証）:

1. **Deep OC-SORT側の改善**: IDスイッチ自体を防ぐ（トラッカーのパラメータ調整、または別のトラッカー検討）
2. **Re-ID特徴量の保護**: 遮蔽発生時にEMA更新を停止する、またはBBのIoU急変を検出して特徴量更新をスキップする
3. **アクティブstable_id間の再マッチング**: 現状は`_disappeared`のみと比較するが、アクティブなstable_id同士の入れ替わりを検出する仕組みを追加する

### 1.4 影響範囲

- 室内動画では頻繁に発生する（看護師が対象の前を横切るシーン）
- camSony1_Lの362回の出現/消失イベントのうち、長時間消失（1000フレーム以上）が20件以上
- 「見切れ（画面外退出）」だけでなく「前方遮蔽（他者による遮蔽）」がトラッキング失敗の主要因

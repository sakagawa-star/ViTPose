# feat-026: 見切れ再同定の検証

## ステータス: Open

## 概要

camSony1_L（長尺動画、321,239フレーム、約3時間）でカスタムRe-ID（遅延マッチN=180）の見切れ再同定精度を検証する。

検証観点:
1. 見切れ後に戻ってきた同一人物に同じstable_idを割り当てるか（再同定の正確性）
2. 異なる人物に同じstable_idを割り当てないか（誤同定の防止）

feat-022ではcamSony1_S（900フレーム、見切れ区間のクリップ）で92.8%の収束率を確認済み。本案件では全体を通した検証を行う。

## 依存

- feat-022（カスタムRe-IDモジュール）— 完了済み
- feat-025（BB重複除去方式）— 完了済み
- **feat-028（JSONにトラッキングID記録）— 完了済み（2026-04-07）**

## 現在の進捗

- FR-001〜FR-004: 実装済み・テスト済み
- FR-005（目視検証）: stable_id=1の検証動画を生成し、目視検証を実施
- **検証結果: 不合格** — Deep OC-SORTのIDスイッチ（track_id乗っ取り）により、横切り人物通過後にstable_id=1の追跡が途切れる問題を確認
- 原因調査完了: `investigation.md` に詳細を記録済み

## 調査結果サマリー

- **根本原因**: Deep OC-SORTのIDスイッチ発生時に、`custom_reid.py` のステップ3（EMA特徴量更新）が無条件に実行されるため、stable_id=1の特徴量が横切り人物のもので汚染される
- **最大消失区間**: フレーム6856→82583（75,727フレーム≒42分間）
- 詳細は `investigation.md` を参照

## 次のステップ

EMA更新前に現在の特徴量と新特徴量の類似度をチェックし、類似度が閾値以下なら更新をスキップする修正を検討中

# feat-016: JSONにBBスコアを保存 — 要求仕様書

## 1.1 プロジェクト概要

- **何を作るか**: OpenPose JSON出力に人物検出のバウンディングボックス(BB)スコアを含める機能
- **なぜ作るか**: 現在のJSON出力にはBBスコアが保存されておらず、誤検出の分析や後処理でのフィルタリングに再推論が必要。BBスコアをJSON内に保持することで、後工程での品質フィルタリングを可能にする
- **誰が使うか**: 本プロジェクトの開発者（Pose2Simへの入力前処理として利用）
- **どこで使うか**: HALPE 26統合パイプライン（`scripts/run_halpe26_pipeline.py`）

## 1.2 用語定義

| 用語 | 定義 |
|------|------|
| BBスコア | Faster R-CNNが出力する人物検出の信頼度スコア（0.0〜1.0） |
| OpenPose JSON | Pose2Sim互換のキーポイント出力フォーマット（version 1.3） |
| `wb_results` | WholeBody推定の結果リスト。各要素に `bbox` キー（[x1,y1,x2,y2,score]）を持つ |

## 1.3 機能要求一覧

### FR-001: JSON出力にBBスコアを追加

- **機能名**: BBスコアのJSON出力
- **概要**: 各人物のOpenPose JSONエントリに `bbox_score` フィールドを追加する
- **入力**: `wb_results[i]['bbox']`（shape=(5,)、5番目の要素がスコア）
- **出力**: JSONの各personオブジェクトに `"bbox_score": float` を追加
- **受け入れ基準**: 出力JSONの各personオブジェクトに `bbox_score` キーが存在し、値がFaster R-CNNの検出スコアと一致する

## 1.4 非機能要求

- **パフォーマンス**: BBスコアの追加による処理時間の増加は無視できるレベル（floatを1つJSONに追加するだけ）
- **互換性**: Pose2Simは未知のキーを無視するため、既存の互換性を維持する

## 1.5 制約条件

- `halpe26_to_openpose_json` 関数のインターフェース変更が必要（BBスコアを受け取るパラメータを追加）
- `halpe26_to_openpose.py` の単体スクリプト（`main`関数）も同様に対応する

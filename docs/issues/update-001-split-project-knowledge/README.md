## 取り込む候補ごとの経緯と目的

### K1: `docs/PROJECT_KNOWLEDGE.md` の新設と `CLAUDE.md`「プロジェクト知識」節

- **(a) 契機**: honOCR で、知識の追記という日常的な操作が毎回「統治文書の編集」になり、`CLAUDE.md` への正当な編集が頻繁なため不適切な編集が紛れても目立たない問題が顕在化した（honOCR feat-018 のインシデント調査）。honOCR は `CLAUDE.md` の全17コミットを集計し、feat 案件が更新したのは知識4セクションのみ・統治部分への更新は0回と実測した
- **(b) 目的**: 統治（update 案件のみが更新）と知識（feat/bug の完了処理が更新）をファイル境界で分け、「`CLAUDE.md` を変更する」行為を稀な例外にする。知識は1ファイルに集約し必読指示を1つにする（ADR-1）
- **(c) 形式の理由**: 3セクション（データ / ディレクトリ構成 / ドメイン知識）を1ファイルにまとめる（ADR-1。分割は肥大化時に検討）。分割検討の閾値は 500 行で、分割は強制せず判断と理由を記録する（ADR-2）。`CLAUDE.md` に要約を残さない（ADR-3）。update 案件の定義に「`docs/PROJECT_KNOWLEDGE.md` の内容改訂を目的とする update 案件は起票しないが、update の完了処理でディレクトリ構成は更新する」の但し書きを置く（ADR-7。honOCR 版の「対象外」の断定は R4 と矛盾したため、テンプレートで書き分けた。テンプレート update-009 codex-01 中2）。テンプレートの節名は「テストデータ」ではなく「データ」（実データ・テストデータの双方を扱うため。同案件の固有の判断2）
- **(d) 保持すべき制約**: 「必読」「更新の役割分担（非対称ルール）」の3項目（内容は完了処理で更新・構成変更は update 案件・`CLAUDE.md` の変更は update 案件のみ）は文言を変えない。`CLAUDE.md` に知識の要約を残さない。分割検討の閾値 500 行と記録の義務を残す
- **(e) 典拠**: テンプレート `docs/issues/update-009-from-honocr-project-knowledge/README.md`（目的・背景、ADR 表）、同 `design.md` 8章、同 `reviews/codex-01.result.md`（中1〜3）・`codex-04.result.md`（収束）

**本リポジトリ向けの読み替え**:

- テンプレートの3セクションはプレースホルダだが、本リポジトリには実記述がある。移動は**無改変の転記**とする（honOCR ADR-6 と同じ。テンプレート update-009 では「プレースホルダのため該当しない」とされたが、実記述を持つ本リポジトリには当てはまる）
- 本リポジトリの知識は3分類より細かい（MoE の仕組み・キーポイント定義・パイプライン構成・関連リポジトリ）。これらはドメイン知識の下位節として転記する（各節の対応は `design.md`）
- 「`CLAUDE.md` の変更は update 案件でのみ行う」は、update フローが本リポジトリに入る（2件目）までの間、参照先がテンプレートにしかない。その間の扱いを `CLAUDE.md` に暫定注記として置く（`design.md`）

### K3: `docs/CHANGELOG.md` の導入と「完了済み案件」のポインタ化

- **(a) 契機**: テンプレート側の文書からは確認できない。テンプレート update-001 は「調査・計画は反映元で作成された反映依頼書が担い、反映完了後に削除した」と記録しており（同 README「注記」）、CHANGELOG を導入した反映元（lift2d）での契機は残っていない。lift2d でも CHANGELOG は初回コミット（2026-03-13）から存在し、導入の経緯を記した案件文書はない。**本リポジトリ側の契機**は上記「背景・変更理由」のとおり（「完了済み案件」節の肥大）
- **(b) 目的**: テンプレート update-001 README の反映内容3・4に記録されている: 完了ステップで CHANGELOG に完了内容を記録し、`CLAUDE.md` の肥大化を防ぐ（完了済み案件はポインタ1行）。加えて K1 の非対称ルール（`CLAUDE.md` は update 案件でのみ変更）により、完了のたびに追記される履歴は `CLAUDE.md` に置けない
- **(c) 形式の理由**: テンプレートの雛形は「日付見出しの下へ完了内容を記録し、新しい日付を上に置く」。文面の選定理由・採らなかった案は反映元に記録がない
- **(d) 保持すべき制約**: `CLAUDE.md`「完了済み案件」節はポインタ1行（`docs/BACKLOG.md`（一覧）と `docs/CHANGELOG.md`（リリース履歴）を参照）にする。完了履歴を `CLAUDE.md` に再び置かない
- **(e) 典拠**: テンプレート `update-001-from-lift2d/README.md`（反映内容3・4、注記）、テンプレート `template/docs/CHANGELOG.md`、テンプレート `update-009-.../design.md` 4.2（R6: 禁止事項に CHANGELOG を含む）

**(a) が反映元で確認できないことの扱い（要ユーザー確認）**: テンプレートの規定では、経緯が反映元の文書から確認できない候補は、推測で補わずユーザーに確認するか取り込まない。(b) 目的は反映元に記録があり、本リポジトリ側の契機も実在するため取り込みを提案するが、ユーザーの確認を得てから反映する（2026-10-05 ユーザーが取り込みを承認）。

# feat-052 要求仕様書: 服パッチ静止画からの服色特徴量分析・HSVレンジ提案ツール

作成日: 2026-05-26
準拠: `docs/REQUIREMENTS_STANDARD.md`

---

## 1.1 プロジェクト概要

- **何を作るか**: 患者の服が写った静止画1枚を入力に、ViTPoseで胴体領域を切り出し、その領域のHSV色特徴量を測定し、`postprocess_pink_id.py` 用の推奨HSVレンジ（`FIXED_HSV_RANGES`）と推奨ピンク比率閾値（`MIN_PINK_RATIO`）の判断材料を提示するCLI診断ツール `scripts/analyze_clothing_color.py`。
- **なぜ作るか**: 本番患者にピンク患者追跡（feat-033）を適用したが、HSV色特徴量がテスト動画由来のまま流用され、本番患者の淡いピンク服とズレている。`testdata/E0014-01.png`（本番取りこぼし実例）の事前実測で、現状レンジでの pink_ratio=0.0273（閾値0.03割れ）、彩度中央値26で `S>=60` 充足画素が4.2%しかないことを確認。本番患者の服色を実データから測り、レンジを補正する必要がある。
- **誰が使うか**: 開発者（本人）。新しい患者・服色に対してピンク追跡を適用する前に、その服色に合ったHSVレンジを決めるために使う。
- **どこで使うか**: 既存MMPose環境（Python 3.10.16、uv管理、CUDA GPU）。ローカルCLIで単発実行。

## 1.2 用語定義

- **服パッチ静止画**: 患者の服が画面の大部分を占める静止画。顔・全身は含まない（プライバシー保護）。例: `testdata/E0014-01.png`
- **胴体ROI**: HALPE26 胴体4点（左肩=5・右肩=6・左腰=11・右腰=12）の信頼できる点から構成する軸並行最小矩形領域。色測定の対象領域
- **pink_ratio**: ROI内の全画素のうち、指定HSVレンジに含まれる画素の比率（値域 [0.0, 1.0]）。`compute_pink_ratio` が算出
- **FIXED_HSV_RANGES**: `postprocess_pink_id.py` のピンク判定HSVレンジ定数。`[((H_lo,S_lo,V_lo),(H_hi,S_hi,V_hi)), ...]` 形式（H:[0,179], S/V:[0,255]）
- **MIN_PINK_RATIO**: `postprocess_pink_id.py` で pink_id=1 候補とする最低 pink_ratio（現状デフォルト0.03）
- **現状レンジ**: `postprocess_pink_id.py` の現行 `FIXED_HSV_RANGES`（赤系ピンク・マゼンタ・ピンク赤尾部の3レンジ）
- **推奨レンジ**: 本ツールが入力画像から算出して提案するHSVレンジ
- **無彩色画素**: 彩度または明度が低く色相が不安定な画素（背景の寝具・影等の低彩度または低明度の画素）。色相推定から除外する対象
- **有彩色画素率**: ROI内全画素のうち、無彩色除外後に残る画素の割合（値域 [0.0, 1.0]）
- **色相環またぎ**: 赤・ピンク系の色相がHSVのH=0境界の両側（0付近と179付近）に分かれる現象
- 本ドキュメントの用語は機能設計書・コード内でも同一の語を使う

## 1.3 機能要求一覧

### FR-001 静止画ポーズ推定
- **機能名**: 画像全体1BBでのViTPose推論
- **概要**: 入力静止画の全体を1つのバウンディングボックス（`[0, 0, W, H, 1.0]`）としてViTPose（WholeBody + AIC）に渡し、HALPE26キーポイント（26点×(x,y,conf)）を取得する
- **入力**: 静止画ファイルパス（CLI引数）。`cv2.imread` で読める形式（PNG/JPG）、BGR、任意サイズ
- **出力**: HALPE26キーポイント配列（26点、各 (x, y, conf)）
- **受け入れ基準**: `testdata/E0014-01.png` に対して実行し、胴体4点（5/6/11/12）のうち2点以上が conf >= `--kpt-conf-min`（デフォルト0.3）で得られること（本基準は `testdata/E0014-01.png` に限定する。胴体が写りにくい他画像では2点未満となり得るが、その場合は FR-007 のフォールバックで正常動作すればよい）

### FR-002 胴体ROI構築
- **機能名**: 胴体4点からの矩形ROI構築
- **概要**: HALPE26胴体4点（5/6/11/12）の信頼できる点（conf >= conf_min）から軸並行最小矩形ROIを構築する。`postprocess_pink_id.py` の `build_keypoint_rect_roi`（feat-046）を再利用
- **入力**: HALPE26キーポイント（flat list）、画像幅・高さ、conf_min、area_min
- **出力**: ROI矩形 (x1,y1,x2,y2) と構築ステータス（"ok" / "fail_kpt" / "fail_area"）
- **受け入れ基準**: 構築成功時は元画像内に収まる矩形（x2>x1, y2>y1, 面積>=area_min）を返す。失敗時はFR-007のフォールバックに従う

### FR-003 ROI内色測定（出力a）
- **機能名**: HSV色特徴量の測定
- **概要**: ROI内画素のHSV分布を測定する。無彩色画素を除外した上で、H/S/V各チャンネルのパーセンタイル、有彩色画素率、現状レンジでのpink_ratioを算出する
- **入力**: ROI内のBGR画素、無彩色除外閾値（sat_min, val_min）、パーセンタイル幅、現状FIXED_HSV_RANGES
- **出力（コンソール標準出力）**:
  - H/S/V各チャンネルの p_low / 中央値 / p_high（整数。無彩色除外後の画素で算出）
  - 有彩色画素率（[0.0, 1.0]、小数3桁）
  - 現状レンジでのpink_ratio（[0.0, 1.0]、小数4桁）
- **受け入れ基準**: `testdata/E0014-01.png` の胴体ROIで現状レンジpink_ratioが 0.03 未満（＝本番取りこぼしの再現）であること。全数値が値域内であること

### FR-004 可視化PNG出力
- **機能名**: 測定結果の可視化
- **概要**: 元画像・ROI枠・現状/推奨レンジのピンクマスク・H/S/Vヒストグラムを1枚のPNG画像に合成して保存する
- **入力**: 元画像、ROI矩形、現状マスク、推奨マスク、HSV分布
- **出力（PNGファイル）**: 保存先はCLI引数 `--out`（デフォルト: 入力画像と同じディレクトリの `<stem>_color_analysis.png`）。以下4要素を含む:
  - 元画像 + ROI枠（矩形を線で重畳）
  - ROIの現状レンジ・推奨レンジのピンクマスク（2種）
  - H/S/Vヒストグラム（各チャンネル、無彩色除外後）
  - 推奨レンジ・ビフォーアフター pink_ratio のテキスト
- **受け入れ基準**: 実行後にPNGファイルが生成され、上記4要素が判別可能な形で含まれること（目視確認）

### FR-005 推奨HSVレンジ算出・提示（出力b）
- **機能名**: 推奨HSVレンジとビフォーアフター提示
- **概要**: ROI内の有彩色画素のHSV分布から、色相環またぎに対応した推奨 `FIXED_HSV_RANGES` を算出する。彩度・明度は下限のみデータ駆動（上限は255固定）。現状レンジと推奨レンジのpink_ratioを併記する
- **入力**: ROI内の有彩色画素のHSV分布、パーセンタイル幅
- **出力（コンソール標準出力）**:
  - 推奨 `FIXED_HSV_RANGES`（Python literal、1〜2レンジ。`postprocess_pink_id.py` にコピペ可能な形式）
  - 推奨S下限・V下限
  - ビフォーアフター: 現状レンジpink_ratio と 推奨レンジpink_ratio（ROI内、小数4桁）
  - MIN_PINK_RATIOに関する注記: 「ROIは服が大部分を占めるため、本値は動画BB内比率の上限。動画では肌・背景が混じり値は低下する」旨を明示
- **受け入れ基準**: `testdata/E0014-01.png` で、推奨レンジのROI内pink_ratioが現状レンジpink_ratioより大きく、かつ 0.03 以上（＝推奨レンジなら候補入りする）であること。推奨レンジがPython literalとして構文的に正しい（リスト of ((int,int,int),(int,int,int))、各値が H:[0,179] / S,V:[0,255] の範囲内）こと

### FR-006 CLI引数
- **機能名**: コマンドラインインターフェース
- **概要**: 以下の引数を受け付ける
- **入力（引数）**:
  - `image`（位置引数、必須）: 入力静止画パス
  - `--out`: 可視化PNG出力パス（デフォルト: `<入力stem>_color_analysis.png`）
  - `--device`: 推論デバイス（デフォルト: `cuda:0`）
  - `--kpt-conf-min`: 胴体点の信頼度下限（float、値域 [0.0, 1.0]、デフォルト0.3）
  - `--min-roi-area`: ROI最小面積（int、値域 >=1、デフォルト200。既存 `build_keypoint_rect_roi` の挙動と揃える。0 を許容すると `area < area_min` 判定が常に偽になり `fail_area` が無効化されるため下限は1とする）
  - `--percentile`: 推奨レンジ算出のパーセンタイル幅（float、値域 [0.0, 50.0]、デフォルト5.0 → 下側5%・上側95%を使用）
  - `--sat-min`: 無彩色除外の彩度下限（int、値域 [0, 255]、デフォルト20）
  - `--val-min`: 無彩色除外の明度下限（int、値域 [0, 255]、デフォルト60）
- **出力**: なし（他FRの動作を制御）
- **受け入れ基準**: `--help` で全引数が表示される。範囲外の値を渡すとエラーメッセージを出して終了コード非0で終了する

### FR-007 ROI構築失敗時のフォールバック
- **機能名**: ROI構築失敗時の画像全体フォールバック
- **概要**: FR-002のROI構築が失敗（fail_kpt / fail_area）した場合、画像全体をROIとして色測定を続行し、警告を表示する
- **入力**: FR-002のステータス
- **出力**: 警告メッセージ（標準出力）「胴体ROI構築失敗（理由: fail_kpt|fail_area）。画像全体をROIとして測定します」。以降のFR-003〜005は画像全体ROIで実行
- **受け入れ基準**: 胴体点が2点未満の画像でもツールが異常終了せず、画像全体ROIで測定結果を出力すること

## 1.4 非機能要求

- **パフォーマンス**: 静止画1枚の処理（モデルロード込み）がCUDA GPU環境で60秒以内に完了する。モデルロードを除く推論〜出力は10秒以内
- **対応環境**: 既存MMPose環境（Python 3.10.16、uv管理）。CUDA対応GPU必須（ViTPose推論のため）。CPU動作は要求しない
- **信頼性**: 入力画像が読めない場合・モデルチェックポイントが存在しない場合は、明示的なエラーメッセージを出して終了コード非0で終了する。PNG保存に失敗した場合は不完全なファイルを残さない（出力先が生成されていれば削除する）
- **セキュリティ**: 入力画像は顔・全身を含まない服パッチ。ツールは画像内容を外部送信せず、ローカル処理のみ

## 1.5 制約条件

- **使用必須ライブラリ**: MMPose 0.24.0（`inference_top_down_pose_model`, `init_pose_model`）、OpenCV（cv2）、NumPy、Matplotlib（ヒストグラム描画。feat-040 `plot_pink_ratio_timeline.py` で使用実績あり）
- **再利用必須**:
  - `scripts/merge_halpe26.py`: WB/AICモデル設定（`WB_CONFIG`/`WB_CHECKPOINT`/`AIC_CONFIG`/`AIC_CHECKPOINT`）・`merge_to_halpe26`（可視化はmatplotlibの`Rectangle`/`imshow`で行うため`draw_halpe26`/`draw_bbox`は使わない）
  - `scripts/postprocess_pink_id.py`: `build_keypoint_rect_roi`・`compute_pink_ratio`・`FIXED_HSV_RANGES`・`MIN_PINK_RATIO`・`TORSO_KEYPOINT_INDICES`
- **使用禁止**: 既存 `postprocess_pink_id.py` / `merge_halpe26.py` のコード変更（本ツールは独立スクリプトとして追加。既存コードに手を入れない）
- **モデル**: `checkpoints/wholebody.pth` / `checkpoints/aic.pth`（既存、feat-002で分割済み）
- **ネットワーク**: オフライン動作（推論はローカルGPU）
- **Python実行**: uv経由（`uv run python`）

# feat-018: JSONにBBのROI座標を保存 — 要求仕様書

## 1.1 プロジェクト概要

- **何を作るか**: OpenPose JSON出力に人物検出のバウンディングボックスROI座標（x1, y1, x2, y2）を含める機能
- **なぜ作るか**: feat-016でBBスコアは保存済みだが、ROI座標がないため後工程で人物領域の位置・サイズを把握できない。ROI座標を保持することで、重複検出の除去や人物領域の分析が可能になる
- **誰が使うか**: 本プロジェクトの開発者
- **どこで使うか**: HALPE 26統合パイプライン（`scripts/run_halpe26_pipeline.py`）

## 1.2 用語定義

| 用語 | 定義 |
|------|------|
| ROI | Region of Interest。人物検出のバウンディングボックスの矩形座標 |
| bbox | `wb_results[i]['bbox']`。numpy.ndarray, shape=(5,), [x1, y1, x2, y2, score] |

## 1.3 機能要求一覧

### FR-001: JSON出力にBB ROI座標を追加

- **機能名**: BB ROI座標のJSON出力
- **概要**: 各人物のOpenPose JSONエントリに `bbox` フィールドを追加する
- **入力**: `wb_results[i]['bbox']`の先頭4要素（x1, y1, x2, y2）。単位はピクセル、float型
- **出力**: JSONの各personオブジェクトに `"bbox": [x1, y1, x2, y2]` を追加。4要素のfloatリスト
- **受け入れ基準**: 出力JSONの各personオブジェクトに `bbox` キーが存在し、値が4要素のfloatリストであること

## 1.4 非機能要求

- **パフォーマンス**: 処理時間への影響は無視できるレベル
- **互換性**: Pose2Simは未知のキーを無視するため、既存の互換性を維持する

## 1.5 制約条件

- `halpe26_to_openpose_json` 関数のインターフェース変更が必要（ROI座標を受け取るパラメータを追加）
- `halpe26_to_openpose.py` の単体スクリプト（`main`関数）も同様に対応する

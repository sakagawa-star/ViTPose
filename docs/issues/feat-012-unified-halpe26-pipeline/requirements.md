# feat-012: HALPE 26統合パイプライン 要求仕様書

## 1. プロジェクト概要

- **何を作るか**: 動画入力に対しHALPE 26キーポイント推定を行い、可視化動画とOpenPose JSON出力を1回の推論で同時生成する統合スクリプト
- **なぜ作るか**: 現状は`visualize_halpe26_video.py`（可視化）と`halpe26_to_openpose.py`（JSON出力）が別スクリプトで、同じ推論を2回実行する必要がある。推論はGPU計算が重い処理であり、1回の推論で両方の出力を得ることで処理時間を半減させる
- **誰が使うか**: 本プロジェクトの開発者（病室動画の2Dポーズ推定パイプラインの運用者）
- **どこで使うか**: CUDA対応GPU搭載のLinux環境

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| HALPE 26 | 26点のキーポイント定義（COCO 17 + Head + Neck + Hip center + 足6点） |
| WholeBody | COCO-WholeBody 133キーポイント推定モデル（足6点の取得に使用） |
| AIC | AI Challenger 14キーポイント推定モデル（Head/Neckの取得に使用） |
| OpenPose JSON | Pose2Sim互換のJSON形式。version=1.3、`pose_keypoints_2d`にキーポイント配列を格納 |
| 可視化動画 | 入力動画の各フレームにHALPE 26のキーポイントとスケルトンを描画した動画 |
| 統合パイプライン | 人物検出→WholeBody推定→AIC推定→HALPE 26結合→可視化+JSON出力を1回で実行する処理フロー |

## 3. 機能要求一覧

### FR-001: 動画からHALPE 26キーポイント推定

- **機能名**: 動画フレームごとのHALPE 26キーポイント推定
- **概要**: 入力動画の各フレームに対し、人物検出→WholeBody推定→AIC推定→HALPE 26結合を実行する
- **入力**: 動画ファイルパス（`--video`引数）
- **出力**: フレームごとのHALPE 26キーポイント（内部データ、後続のFR-002/FR-003で使用）
- **受け入れ基準**: FR-002とFR-003の受け入れ基準が共に満たされること（推論パイプラインの正当性はFR-002の可視化結果とFR-003のJSON出力を通じて検証する）

### FR-002: 可視化動画出力

- **機能名**: HALPE 26キーポイント可視化動画の生成
- **概要**: FR-001の推論結果を使い、各フレームにキーポイントとスケルトンを描画した動画を出力する
- **入力**: FR-001の推論結果、入力動画のフレーム画像
- **出力**: `{out-dir}/vis_halpe26_{video_basename}`（mp4vコーデック。`video_basename`は入力動画の`os.path.basename(video)`）
- **受け入れ基準**: テスト動画（cam05520129.mp4）に対し、既存の`visualize_halpe26_video.py`の出力動画と目視で同一の描画結果が得られること

### FR-003: OpenPose JSON出力

- **機能名**: Pose2Sim互換OpenPose JSON出力
- **概要**: FR-001の推論結果を使い、フレームごとにOpenPose JSON形式でファイル出力する
- **入力**: FR-001の推論結果
- **出力**: `{out-dir}/{video_stem}_json/{video_stem}_{frame:06d}.json`
- **受け入れ基準**: テスト動画（cam05520129.mp4）の先頭10フレームに対し、既存の`halpe26_to_openpose.py`の出力JSONとフレームごとに数値一致すること

### FR-004: 出力モード選択

- **機能名**: 出力内容の選択
- **概要**: コマンドライン引数で出力モードを制御できる。デフォルトは両方出力
- **入力**: `--mode`引数（選択肢: `both`, `video`, `json`）
- **出力**: 選択されたモードに応じた出力ファイル
- **受け入れ基準**:
  - `--mode both`（デフォルト）: 可視化動画とJSON両方を出力する
  - `--mode video`: 可視化動画のみ出力する
  - `--mode json`: JSONのみ出力する

## 4. 非機能要求

- **パフォーマンス**: 推論処理（人物検出+WholeBody+AIC）が動画全体で1回のみ実行されること（既存2スクリプト個別実行では2回必要だった推論を1回に統合）。同一動画に対し、既存2スクリプトの合計処理時間より短い時間で完了すること
- **対応環境**: CUDA対応GPU搭載のLinux環境（既存スクリプトと同一）
- **互換性**: 既存の`merge_halpe26.py`のHALPE 26結合ロジック（`merge_to_halpe26`, `draw_halpe26`）をそのまま使用する
- **信頼性**: 推論途中で異常終了した場合、それまでの出力ファイルは削除しない。JSONは個別ファイルなので部分的に有効。可視化動画は不完全だがデバッグに使用できる

## 5. 制約条件

- 既存の`merge_halpe26.py`の関数・定数を再利用する（重複実装しない）
- 既存の`halpe26_to_openpose.py`の`halpe26_to_openpose_json`関数を再利用する
- MMPoseのコードは変更しない
- 新規ライブラリの追加は不要（既存の依存関係のみで実装可能）

## 6. 優先順位

| ID | 優先度 | 備考 |
|----|--------|------|
| FR-001 | Must | 推論の一本化（本案件の核心） |
| FR-002 | Must | 可視化動画出力 |
| FR-003 | Must | OpenPose JSON出力 |
| FR-004 | Should | モード選択。なくても両方出力で運用可能 |

**MVP**: FR-001〜FR-003（両方同時出力のみ。モード選択なし）

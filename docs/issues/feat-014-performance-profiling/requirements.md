# feat-014: パイプライン処理速度プロファイリング 要求仕様書

## 1. プロジェクト概要

- **何を作るか**: `run_halpe26_pipeline.py` の各処理ステップの所要時間を計測し、ボトルネックを特定するプロファイリング機能
- **なぜ作るか**: 30秒の動画処理に180秒かかっており、処理速度の向上が必要。改善するためにまずボトルネックを特定する
- **誰が使うか**: 本プロジェクトの開発者
- **どこで使うか**: CUDA対応GPU搭載のLinux環境

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| プロファイリング | 各処理ステップの所要時間を計測し、処理時間の内訳を明らかにすること |

## 3. 機能要求一覧

### FR-001: 処理ステップ別の時間計測

- **機能名**: フレームループ内の各処理ステップの所要時間計測
- **概要**: `--profile` オプション指定時に、各処理ステップの累積時間と平均時間を計測・表示する
- **入力**: `--profile` フラグ（指定時のみ計測を実行）
- **出力**: 処理完了後に以下の計測結果を標準出力に表示する
  - 各ステップの累積時間（秒）
  - 各ステップの1フレームあたり平均時間（ミリ秒）
  - 各ステップの処理時間割合（%）。ステップ間のオーバーヘッド（ループ制御、条件分岐等）があるため、合計は100%未満になる場合がある
  - 全体の処理時間（秒）とFPS
- **計測対象ステップ**:
  1. フレーム読み出し（`cap.read()`）
  2. 人物検出（`inference_detector` + `process_mmdet_results`）
  3. WholeBody推定（`inference_top_down_pose_model`）
  4. AIC推定（`inference_top_down_pose_model`）
  5. HALPE 26結合（`merge_to_halpe26`）
  6. 描画（BB + キーポイント + スケルトン。`--mode video`/`both` 時のみ）
  7. JSON出力（`--mode json`/`both` 時のみ）
- **受け入れ基準**: テスト動画（cam05520129.mp4）に対し `--profile` を付けて実行し、各ステップの処理時間内訳が表示されること。`--profile` なしの実行では計測処理が実行されず、既存の動作と同一であること

## 4. 非機能要求

- **パフォーマンス**: `--profile` 指定時の計測オーバーヘッドは `time.time()` 呼び出しのみであり、推論結果に影響しない
- **対応環境**: 既存と同一
- **互換性**: `--profile` なしの実行は既存の動作と完全に同一。出力ファイル（動画・JSON）にも影響しない
- **信頼性**: 計測コードの失敗は推論結果に影響しない。計測結果が不正確になる可能性はあるが、推論結果・出力ファイルは正常に生成される

## 5. 制約条件

- 計測には標準ライブラリの `time` モジュールのみ使用する（新規ライブラリ不要）
- 既存の処理ロジックは変更しない。計測コードを追加するのみ
- `--profile` フラグがない場合、計測コードは実行されない

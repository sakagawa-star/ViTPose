# feat-017: キーポイント描画のconfidence閾値を引数指定可能にする — 要求仕様書

## 1.1 プロジェクト概要

- **何を作るか**: 動画描画時のキーポイントconfidence閾値をCLI引数で指定可能にする機能
- **なぜ作るか**: 現在は `kpt_thr=0.3` がハードコードされており、描画閾値の調整に再実装が必要。閾値を変更して描画結果を比較したいケースがある
- **誰が使うか**: 本プロジェクトの開発者
- **どこで使うか**: HALPE 26統合パイプライン（`scripts/run_halpe26_pipeline.py`）

## 1.2 用語定義

| 用語 | 定義 |
|------|------|
| kpt_thr | キーポイントのconfidenceがこの値を超える場合のみ描画する閾値 |
| confidence | ポーズ推定モデルが出力するキーポイントの信頼度（0.0〜1.0） |

## 1.3 機能要求一覧

### FR-001: CLI引数 `--kpt-thr` の追加

- **機能名**: キーポイント描画閾値のCLI指定
- **概要**: `run_halpe26_pipeline.py` に `--kpt-thr` 引数を追加し、描画時の閾値を指定可能にする
- **入力**: `--kpt-thr` 引数、float型、値域0.0〜1.0、デフォルト値0.3
- **出力**: 指定された閾値で描画された動画
- **受け入れ基準**: `--kpt-thr 0.5` で実行した場合、confidence 0.3〜0.5のキーポイントが描画されないこと。`--kpt-thr` を指定しない場合は従来通り0.3で動作すること

## 1.4 非機能要求

- **パフォーマンス**: 閾値を引数化するだけであり、処理速度への影響なし

## 1.5 制約条件

- `draw_halpe26` 関数（`merge_halpe26.py`）は既に `kpt_thr` 引数を持っている（デフォルト0.3）。関数のインターフェース変更は不要
- `--kpt-thr` は `--mode video` および `--mode both` の場合に有効。`--mode json` の場合は描画を行わないため無視される（JSON出力にはconfidence値がそのまま保存される）

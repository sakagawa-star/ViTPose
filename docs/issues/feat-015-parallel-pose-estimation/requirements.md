# feat-015: WholeBody/AIC並列推論 要求仕様書

## 1. プロジェクト概要

- **何を作るか**: `run_halpe26_pipeline.py` のWholeBody推定とAIC推定を `ThreadPoolExecutor` で並列実行する
- **なぜ作るか**: feat-014のプロファイリングで、WholeBody推定（35.0%、68.6ms/フレーム）とAIC推定（34.3%、67.5ms/フレーム）が処理時間の約70%を占めることが判明。両者は同一の `frame` と `person_results` を入力とし、互いに独立しているため、並列実行により前処理（CPU）のオーバーラップで処理時間を改善できる可能性がある
- **誰が使うか**: 本プロジェクトの開発者
- **どこで使うか**: CUDA対応GPU搭載のLinux環境

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| 並列推論 | WholeBody推定とAIC推定をスレッドプールで同時に実行すること |
| ThreadPoolExecutor | Python標準ライブラリ `concurrent.futures` のスレッドプール実装 |

## 3. 機能要求一覧

### FR-001: WholeBody/AIC並列推論

- **機能名**: WholeBodyとAICの並列実行
- **概要**: フレームループ内のWholeBody推定（ステップ5b）とAIC推定（ステップ5c）を `ThreadPoolExecutor` で並列実行する
- **入力**: 既存と同一（`frame`, `person_results`）
- **出力**: 既存と同一（`wb_results`, `aic_results`）。推論結果は逐次実行時と数値一致すること
- **受け入れ基準**:
  - テスト動画（cam05520129.mp4）の先頭10フレームに対し、逐次実行時のJSON出力と並列実行時のJSON出力が `diff` コマンドで完全一致すること。浮動小数点の丸め誤差により完全一致しない場合は、各キーポイント座標の差が 1e-4 以下であることを確認する
  - `--profile` で計測し、WholeBody+AICの合計処理時間が逐次実行時（約136ms/フレーム）より短縮されること。短縮されない場合は、並列化の効果がないことを確認結果として記録し、コードを元に戻す

## 4. 非機能要求

- **パフォーマンス**: 並列化により処理速度が改善されること。改善されない場合はコードを元に戻す（実験的な案件）
- **対応環境**: 既存と同一
- **互換性**: 推論結果は逐次実行時と完全に一致すること。出力ファイル（動画・JSON）に差異がないこと
- **信頼性**: スレッド内で例外が発生した場合、`future.result()` で例外が再送出されるため、既存のエラーハンドリングと同等の動作になる

## 5. 制約条件

- 使用するのは標準ライブラリの `concurrent.futures.ThreadPoolExecutor` のみ（新規ライブラリ不要）
- 既存のMMPose APIを変更しない
- プロファイリング機能（`--profile`）は維持する。並列実行時はWholeBody+AICの合計時間を `pose` として1つの計測項目にまとめる

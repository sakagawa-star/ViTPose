## 捨てた選択肢と理由

- **PyTorch cu126**: sm_120 をサポートしていない。`CUDA error: no kernel image is available for execution on the device` エラー
- **mmcv-full 1.5.0**: PyTorch 2.11 のC++ヘッダ（Float8型等）と非互換でソースビルド不可
- **mmcv-full 1.5.0 プリビルドwheel**: CUDA ops (`_ext.so`) が含まれず `ModuleNotFoundError: No module named 'mmcv._ext'`
- **mmcv 2.x**: MMPose 1.x 用であり MMPose 0.24.0（本リポジトリ）と非互換
- **pyproject.toml に [project] セクション**: 既存 setup.py と競合し editable install が失敗
- **uv pip install でのmmcvインストール**: MMCV_WITH_OPS=1 環境変数が反映されない。pip直接 + setup.py develop で解決
- **mim download mmpose**: ViTPoseフォークにmodel-index.ymlがなく失敗。HRNetチェックポイントは直接URLからwget

## ハマりどころ

- mmcv-full のプリビルドwheelは見つかるが CUDA ops なしでインストールされる。`--no-binary` `--no-cache` を指定しても uv のキャッシュが効いてソースビルドされない場合がある
- mmcv 1.7.2 のソースビルドで `pip install .` はwheel作成時にファイルパスエラー（`[Errno 2] No such file or directory: 'build/bdist.linux-x86_64/wheel'`）。`setup.py develop` で回避
- xtcocotools が numpy 2.x と非互換（`numpy.dtype size changed`）。`--no-build-isolation` で再ビルドが必要
- uv pip install が pyproject.toml の `[[tool.uv.index]]` を優先するため、pip 直接実行でないと別インデックスからインストールできない場合がある

## 学び

- RTX 5060 Ti (Blackwell, sm_120) には PyTorch cu128 以上が必要
- mmcv-full 1.x 系は 1.7.2 が最終版。PyTorch 2.11 とのソースビルドは 1.7.2 なら可能
- mmcv 1.7.2 は mmcv 1.5.0 と後方互換（mmpose 0.24.0 のバージョンチェック緩和だけで動作）
- uv と pip の挙動差に注意: 特にインデックスURL指定、ビルド隔離、環境変数の扱い

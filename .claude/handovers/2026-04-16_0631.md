## 決定事項

### feat-035 の主要な設計判断（design.md ADR と一致）

- **ADR-001: 生 dict 保持設計の採用**: 入力 JSON を `json.load()` で辞書として読み込み、`people[*]` に `track_id` キーを追加するだけで出力。feat-033 ADR-001 踏襲。既存フィールド（`stable_id`, `pink_id`, `version`, `person_id`, `pose_keypoints_2d`, `bbox`, `bbox_score` 等）を一切変更しない
- **ADR-002: IoU マッチング方式を採用**（`det_ind` 方式を却下）: `postprocess_reid.py` の `assign_stable_ids` 相当を `assign_track_ids` に改名・改変して流用。Deep OC-SORT 戻り値第 7 列の `det_ind` は内部実装依存で将来変更リスクあり
- **ADR-003: `custom_reid.py` 依存を完全削除**: `postprocess_reid.py` に `--no-reid` フラグを追加する案を却下、新規スクリプトとして切り出し
- **ADR-004: 入力 JSON がないフレームでも `tracker.update(空 dets, frame)` を呼ぶ**: Deep OC-SORT の `max_age` 判定が `frame_count` ベースで動くため、スキップすると古い track が淘汰されずに残留する。ただし出力 JSON は書き出さない（AC-005-2 を守る）
- **ADR-005: 1 ファイル完結**: `compute_iou` や `assign_track_ids` の共通モジュール切り出しはしない（早すぎる抽象化を避ける、既存流儀と揃える）
- **ADR-006: ログは `print()`**: `logging` 導入なし（既存スクリプトと統一）

### track_id の仕様

- 型: int、値域: Deep OC-SORT が発番する 1 以上の正整数 / マッチなし・無効人物は `-1`
- タイブレーク: IoU 同値時は最小 `track_id` を優先（`postprocess_reid.py` と同じ `elif iou == best_iou and best_tid is not None and tid < best_tid` ロジック）
- 貪欲 IoU 最大方式。ハンガリアン法は使わない。同一 `track_id` が 1 フレーム内で複数人物に割り当たることは仕様として許容（BB 重複除去の完全性は feat-025 の責務）

### NFR-004 メモリ基準の緩和

- 当初「500 MB 以下を受け入れ条件」としたが、設計書 §7.2 の見積もり（321K フレーム × 1 KB × 3 人 × Python dict 倍率 2-3 = 2〜3 GB）と矛盾するため修正
- 最終基準: **OOM で異常終了せず完走**が必須、500 MB は目標値。camSony1_L 実測で OOM 回避・完走を確認済み

### 手動テスト粒度ルール（新規メモリ）

- 手動テストで 1 サンプル（1 フレーム等）で確認できることは、全件網羅用の一時スクリプトを作らずワンライナーで済ませる
- `/tmp/verify_feat035.py` を作ろうとしたがユーザーが却下、1 フレームの `uv run python -c` で十分と判断した経験からメモリ化
- 全件網羅が本当に必要な場面（回帰テスト等）のみスクリプト化する

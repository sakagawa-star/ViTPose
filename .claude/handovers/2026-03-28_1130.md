## 決定事項

- mmcvの `load_checkpoint` はデフォルトで `strict=False` → 分割チェックポイントの余分キー（`mlp.experts.*`, `associate_keypoint_heads.*`）はエラーにならない
- `coco.pth` は `associate_keypoint_heads.*` が残存（COCO分割パスに削除コードがない）。AIC〜WholeBodyの `.pth` は `associate_keypoint_heads` 除去済み、`mlp.experts.*` のみ残存（model_split.py 98行目バグ）
- COCO の `keypoint_head.final_layer.weight` shape[0] は17（事前予想の「17以上」ではなく正確に17）
- Pose2Sim互換のJSON version は 1.3（halpe26_merge_spec.md の 1.0 ではなく、Pose2Sim poseEstimation.py に合わせた）
- Pose2Sim JSON命名規則: `{video_stem}_json/` ディレクトリ、`{video_stem}_{frame:06d}.json` ファイル名
- 人物検出は1回のみ行い、WholeBodyとAICで共有（同じ `person_results` + 同じ `bbox_thr=0.3` で人物対応を保証）
- 動画処理でWholeBody/AIC結果数不一致時はスキップ（RuntimeErrorで停止しない）
- 可視化はOpenCV直接描画（MMPoseの `vis_pose_result` はHALPE 26非対応のため）
- ViTPose++の推論は決定的（同一入力で毎回同一結果）

## 捨てた選択肢と理由

- **CLIでのOneDriveダウンロード**: 認証リダイレクト・JavaScript依存で不安定。ブラウザ手動DLを採用
- **model_split.py のバグ修正**: CLAUDE.md方針「MMPose版コードは可能な限り変更せず」に従い修正しない
- **MMPose `vis_pose_result` でのHALPE 26可視化**: HALPE 26用のdataset_info定義が必要になるため却下。OpenCV直接描画で対応
- **merge_halpe26.py に動画機能を統合**: 単一責務を保つため、動画処理は別スクリプト（visualize_halpe26_video.py）に分離
- **JSON version 1.0**: halpe26_merge_spec.md記載の値だが、Pose2Sim互換を優先して1.3を採用

## 決定事項

- **BoxMOT + Deep OC-SORTのRe-ID**: 病室動画で5〜10秒の見切れ後のID再同定に失敗。パラメータ調整では改善不可能。Re-IDモデルのドメイン不適合が根本原因
- **検出器変更の方針**: 2段階で検証する
  1. YOLOX-l（MMDet 2.28.2互換、mAP 49.4、コード変更最小）
  2. ダメならYOLO11x（最高精度 mAP 54.7、`uv pip install ultralytics`）
- **検証方法**: `scripts/run_halpe26_pipeline.py` のコピーを作成し、コピー側で検出器を差し替えて検証する
- **検証は案件として管理**: 管理番号を発番する（次セッションで実施）
- **開発フロー厳守**: Subagentレビュー後、ユーザーのレビュー・承認を待ってから実装に進むこと（今回の反省）

## 捨てた選択肢と理由

- **max_ageパラメータ調整によるID維持改善**: max_age=30〜300の全パターンで結果が同一。追跡保持の問題ではなく、Re-IDマッチング失敗が原因
- **Re-IDパラメータ調整**: w_association_emb、alpha_fixed_emb、det_thresh、min_hitsを調整したが改善なし
- **検出途切れを減らすアプローチ**: ユーザーから「人が完全に映っていない5〜10秒の後でもトラッキングすべき」と明確に否定された。検出途切れを減らすのは要件のすり替え
- **RTMDet**: MMDet 3.x必須。MMPose 0.24.0との互換性が崩れるリスクがあり非推奨
- **YOLOX-lとYOLO11xの間の中間ステップ（YOLOX-x, YOLOv8l等）**: mAP差が小さく、途中で試す意味が薄い

## ハマりどころ

- **開発フロー違反**: feat-020でSubagentレビュー後、ユーザーのレビューを待たずに実装を開始してしまった。ユーザーから指摘を受け、レビューからやり直した
- **BoxMOT APIの不一致**: Web情報では `DeepOCSORT` / `model_weights` / `fp16` と記載されていたが、実際のv16.0.11 APIは `DeepOcSort` / `reid_weights` / `half`
- **max_age変更が効かない**: コンストラクタの引数リストに `max_age` がなく、`**kwargs` 経由で渡す必要がある。初期化ログで値を確認して渡せていることは確認済みだが、結果は変わらなかった

## 学び

- **BoxMOT DeepOcSort の実APIは公式ドキュメントと異なる**: 必ず `inspect.signature()` や `dir()` で実際のAPIを確認すべき
- **Re-IDモデル（OSNet/MSMT17）は歩行者ドメインに特化**: 病室の臥位患者では外見特徴が大きく異なり、再同定が機能しない
- **Faster R-CNN R50-FPNは臥位の人物検出に弱い**: COCOデータセットに臥位の画像が少ないため、横になった体を部位ごとに別の人物として誤検出する
- **パラメータ調整の限界**: Re-IDのドメイン不適合が原因の場合、トラッカーのパラメータをどう調整しても改善しない
- **ユーザーにとって5〜10秒の見切れは「短時間」**: 1時間動画の文脈では当然。この要件を満たせないトラッキングは実用に耐えない
